## 维护规则

1. **先登记后动手**：凡修复 Bug，开工前必须先在本表登记（禅道编号、标题、模块、日期、状态）；AI 修 Bug 前必须先读本表确认已登记。
2. **全过程更新**：根因、改动文件、部署/验证状态记录在同一行，随修复进展持续更新。
3. **状态流转**：`🔧 修复中` → `✅ 已修复待验证`（DEV 验证通过）→ `📋 已关闭`（用户验证 / UAT 发布）。
4. **无禅道编号的 Bug**（口头反馈、自查发现）同样登记，编号列填「无」并备注来源。
5. **commit message 关联禅道编号**，如 `fix(tradestpayterm): 事业部带出及审批共享修复 (#1151)`。
