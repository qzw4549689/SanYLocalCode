## 5. 根因分析

### 5.1 根因一：无真实数据的内部指标被当成有效值 0 参与评分

`ScoreCalculator.CalculateQuantitativeScore` 只判断 `value == -1` 时视为缺失：

```csharp
private int CalculateQuantitativeScore(ScoringCardConfig config, decimal value)
{
    if (value == -1)
    {
        return 0;
    }
    // ...
}
```

但 `CofaceDataSyncPlugin` / `CustomerTagInitPlugin` 在创建无数据源标签时，可能写入了 `0` 或 `null` 被默认转为 `0`，导致 `ScoreCalculator` 把 `0` 当成有效值，命中评分卡最低档（通常对应"无逾期"/"无采购"/"无模型分"），反而获得高分。

涉及指标：
- `SalesAmount`（历史采购金额）— CRM 接口待确认
- `ARAmount`（历史逾期金额）— BW 接口待确认
- `ARAge`（历史逾期账龄）— BW 接口待确认
- `OverdueModel`（逾期未回收率模型分）— 人工复核录入，但当前未录入

### 5.2 根因二：客户评级"S级"未归一化为"S"

`ScoreCalculator.NormalizeQualitativeValue` 只处理了 `低风险/中风险/高风险/缺失`，未处理 `S级/A级/B级/C级`：

```csharp
switch (value.Trim())
{
    case "低风险": return "L";
    case "中风险": return "M";
    case "高风险": return "H";
    case "缺失": return "O";
    default: return value.Trim();
}
```

导致标签值 `S级` 与评分卡配置 `list=S` 不匹配，`BigAccount` 实际应得的 10 分丢失。

### 5.3 根因三：标签得分值回写不稳定

`CreditScoreCalculationPlugin.SaveTagScores` 在更新 `mcs_customer_tag.mcs_scorevalue` 时 catch 异常但不 rethrow：

```csharp
catch (Exception ex)
{
    _tracer.Trace($"回写标签得分失败: ...");
    // 不回抛
}
```

当前数据库中大部分标签的 `mcs_scorevalue` 仍为 0（只有 RegisteredCapital=2、SalesAmount=4、OverdueModel=30 被写入），说明回写存在部分失败或被覆盖的情况，但 Plugin Trace 中没有明显报错。

## 10. 修复记录

### 10.1 修复内容

已修改 `Code/Customizations/Plugins/CreditScore/Calculator/ScoreCalculator.cs`：

1. **无真实数据的内部指标按缺失处理**
   - 在读取 `mcs_itemintvalue1`/`mcs_itemvalue1`/`mcs_itemintvalue2`/`mcs_itemvalue2` 前，先判断 `value1` 或 `value2` 任一字段是否有真实数据。
   - 若均无真实数据，将 `decimalValue` 设为 `-1`（缺失标记），`CalculateQuantitativeScore` 识别 `-1` 后直接返回 0 分，避免把默认值 `0` 当成有效值命中最低档。

2. **OverdueModel 按比例计算**
   - 定量评分后增加特殊处理：`itemCode == "OverdueModel"` 时，按 `weight * value / 100` 重新计算得分，替代原先 `[0,100)` 区间固定得 30 分的逻辑。

3. **BigAccount 中文级别归一化**
   - `NormalizeQualitativeValue` 增加映射：
     - `S级` → `S`
     - `A级` → `A`
     - `B级` → `B`
     - `C级` → `C`
   - 同时保留已有 `低风险/中风险/高风险/缺失` → `L/M/H/O` 的映射。

4. **得分回写失败时中断流程**
   - `SaveTagScores` 中回写 `mcs_scorevalue` 失败时，由原先仅记录 Trace 改为抛出 `InvalidPluginExecutionException`。
   - 避免明细得分与总分不一致时被静默忽略。
