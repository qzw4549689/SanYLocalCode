# D365 客户信用评估系统 — 中英多语言实施方案

> **目标**：将客户信用评估模块（含 Phase 1~7 已上线及待上线内容）从当前「单中文显示」改造为支持 **英文(1033) + 简体中文(2052)** 的双语显示。  
> **覆盖范围**：导航(SiteMap)、视图(View)、表单(Form)、字段、Tab/节名称、选项集、按钮/命令、前端 HTML/JS 提示文本。  
> **适用环境**：DEV1 → UAT → 生产，按 Solution 归集发布。  

---

## 1. 现状诊断

### 1.1 元数据层（后端）：中英标签已"占位"，但英文也是中文

当前 `LabelHelper.Create(text)` 已默认同时写入 **1033(英文)** 和 **2052(简体中文)** 两个 `LocalizedLabel`：

```csharp
// Code/Tools/D365ToolCommon/Metadata/LabelHelper.cs
public static readonly int[] DefaultLanguageCodes = { 1033, 2052 };
public static Label Create(string text) => Create(text, DefaultLanguageCodes);
```

但所有调用处只传了一个中文字符串，导致 D365 里英文用户看到的也是中文：

```csharp
// EntityManager.cs 示例
DisplayName = LabelHelper.Create("客户信用评估记录"),   // 英文用户也看到中文
```

**结论**：元数据多语言的"骨架"已经搭好，缺的是真正的英文翻译内容。

### 1.2 前端层：已有 `ms_languagefile_1033/2052` WebResource 机制

项目在 `entity_20260603_peter` Solution 中已有两个语言包 WebResource：

| WebResource | 用途 | 当前内容 |
|-------------|------|----------|
| `ms_languagefile_1033{guid}` | 英文提示文本 | 配件/通用条款等模块的英文提示 |
| `ms_languagefile_2052{guid}` | 中文提示文本 | 配件/通用条款等模块的中文提示 |

这些 JSON 文件供前端 HTML/JS 通过 `Xrm.Utility.getGlobalContext().getCurrentTheme()` 或固定语言读取，主要覆盖弹窗、按钮、校验提示等**前端自定义文本**。

**结论**：前端自定义文本的多语言"容器"已存在，但客户信用评估模块（Coface/评分卡/评估记录/标签等）尚未往里面补充 key。

### 1.3 表单/视图/导航层：目前没有独立维护多语言

- SiteMap、FormXml、ViewXml、App Action/Ribbon 按钮标签都依赖元数据 `LocalizedLabel`。
- 当前这些组件的 Label 都是通过 `LabelHelper.Create(中文)` 一次性写入，英文也是中文。
- 没有独立的"翻译清单"或"语言包 Solution"。

## 2. 总体策略

采用 **"元数据翻译为主 + 前端语言包为辅"** 的双轨方案：

| 层级 | 多语言实现方式 | 是否需改造工具 | 备注 |
|------|---------------|---------------|------|
| **实体显示名/复数名称/描述** | 元数据 `LocalizedLabel` (1033/2052) | ✅ 改造 `LabelHelper` 支持传入翻译 | 用 SDK `UpdateEntityRequest` |
| **字段显示名/描述** | 元数据 `LocalizedLabel` (1033/2052) | ✅ 同上 | 用 SDK `UpdateAttributeRequest` |
| **选项集选项标签** | 元数据 `OptionMetadata.Label` (1033/2052) | ✅ 同上 | 用 SDK `InsertOptionValueRequest` / `UpdateOptionValueRequest` |
| **布尔字段 True/False 标签** | 元数据 `BooleanOptionMetadata.Label` (1033/2052) | ✅ 同上 | 用 SDK `UpdateAttributeRequest` |
| **表单 Tab/Section/字段标签** | FormXml 中 `labels` 节点 (1033/2052) | ✅ 新增工具命令/脚本 | 导出 FormXml → 替换 label → 导入 |
| **视图列名/视图名称** | ViewXml / SavedQuery `LocalizedLabel` (1033/2052) | ✅ 新增工具命令/脚本 | 导出 ViewXml → 替换 label → 导入 |
| **SiteMap 导航项** | SiteMap XML 中 `Title` / `Description` (1033/2052) | ✅ 新增工具命令/脚本 | 通过 App Module SiteMap 编辑器或 SDK |
| **App Action / Ribbon 按钮** | App Action 的 `label` / `tooltip` (1033/2052) | ✅ 新增工具命令/脚本 | 更新 `appaction` 记录 |
| **前端 HTML/JS 提示文本** | `ms_languagefile_1033/2052` WebResource JSON | ✅ 补充 key | 按现有机制扩展 |

**核心原则**：

1. **中英文同时维护**：任何新增/修改标签，必须同时给出中英文，禁止只写中文。
2. **Source of Truth**：以一份 Excel/JSON "翻译总表"作为唯一真相源，禁止在 UI 或代码里零散改翻译。
3. **工具化**：所有元数据翻译通过 C# MetadataTool/DeployTool 脚本化更新，禁止手动在 D365 UI 里逐个改。
4. **增量更新**：已上线的字段不删除重建，只更新 `DisplayName`/`Description` 的多语言 Label。

### 阶段 1：工具改造（2~3 天）

#### 4.1.1 扩展 `LabelHelper` 支持传入多语言文本

将 `LabelHelper.Create(string text)` 扩展为支持多语言文本：

```csharp
public static Label Create(Dictionary<int, string> translations)
{
    if (translations == null || translations.Count == 0) return new Label();

    var localizedLabels = translations
        .Select(kv => new LocalizedLabel(kv.Value, kv.Key))
        .ToArray();

    return new Label(localizedLabels[0], localizedLabels.Skip(1).ToArray());
}
```

并保留现有 `Create(string text)` 作为兼容（用于明确不需要翻译或测试场景）。

#### 4.1.2 改造 `EntityManager` / `MetadataFieldService`

将所有创建/更新实体、字段、选项集的方法，改为接收 `Dictionary<int, string>` 或 `(string zh, string en)` 元组：

```csharp
// 改造前
DisplayName = LabelHelper.Create("客户信用评估记录"),

// 改造后
DisplayName = LabelHelper.Create(new Dictionary<int, string>
{
    [1033] = "Customer Credit Assessment",
    [2052] = "客户信用评估记录"
}),
```

优先改造高频方法：

- `CreateEntity`
- `UpdateEntityDisplayName`
- `UpdateAttributeDisplayName`
- `CreatePicklistField` / `UpdatePicklistOptions`
- `CreateBooleanField`

#### 4.1.3 新增/扩展 MetadataTool CLI 命令

元数据翻译统一通过 **Solution 导入 translations** 完成，不再通过 API 直接写 `LocalizedLabel`。工具命令只保留辅助性质：

| 命令 | 用途 |
|------|------|
| `export <解决方案名> <路径>` | 导出 Solution ZIP，用于核对 `customizations.xml` 中的 `LocalizedNames` |
| `check-labels --entity-prefix mcs_ --languages 1033,2052` | 检查指定前缀实体是否所有 Label 都包含 1033 和 2052 |

> translations 的导出/导入通过 D365 UI 完成（`Settings → Customizations → Export/Import Translations`），不通过 MetadataTool 命令。

#### 4.1.4 新增 DeployTool / MetadataTool 前端语言包更新能力

扩展现有 `ms_languagefile_1033/2052` 的更新方式：

```bash
# 从 JSON 文件更新 WebResource
dotnet run deploy-language-file 1033 /path/to/en.json
dotnet run deploy-language-file 2052 /path/to/zh.json
```

或统一为：

```bash
dotnet run deploy-language-packs /path/to/lang/
```

其中 `/path/to/lang/` 下包含：

```
lang/
├── 1033.json   # 英文
└── 2052.json   # 中文
```

更新后自动发布 WebResource。

### 阶段 2：元数据翻译导入（3~5 天）

**核心原则**：所有元数据翻译统一通过 **Solution 导入 translations** 完成，禁止通过 API/SDK 直接写 `LocalizedLabel`。

标准流程：

1. 在 DEV1 中打开 `Settings → Customizations → Customize the System`。
2. 选择 `entity_YYYYMMDD_peter_trans`（或当前增量 Solution），点击 `Export Translations`。
3. 下载 ZIP，解压后得到 `CrmTranslations.xml` 和 `[Content_Types].xml`。
4. 对照翻译总表，在 `CrmTranslations.xml` 的 `Localized Labels` 工作表中填充英文列（`1033`）。
5. 重新压缩为 ZIP，在 D365 UI 中点击 `Import Translations` 导入。
6. 导入完成后，`Publish All Customizations` 或单独发布涉及的实体。
7. 验证：切换 D365 个人语言为 English，检查字段显示名、视图名称、表单标签是否变为英文。

#### 4.2.1 实体/字段/选项集

这些标签全部在 `CrmTranslations.xml` 的 `Localized Labels` 工作表中：

- 实体显示名/复数名称/描述：`Entity name` + `LocalizedName` / `LocalizedCollectionName` / `Description`。
- 字段显示名/描述：`Entity name` + `Object ID`（字段 GUID）+ `DisplayName` / `Description`。
- 选项集选项标签：`Entity name` + `Object ID` + `OptionLabel`。
- 布尔字段 True/False 标签：`Entity name` + `Object ID` + `TrueLabel` / `FalseLabel`。

#### 4.2.2 表单 Tab/Section/字段标签

表单标签也在 `CrmTranslations.xml` 的 `Localized Labels` 工作表中，对应 `systemform` 记录的 `name` / `description` 等列。

> 注意：D365 表单上的字段标签默认继承字段 DisplayName，但如果表单上被单独覆盖过，需要单独处理。实施时先检查"是否有覆盖"。

#### 4.2.3 视图名称

视图名称对应 `savedquery` 记录的 `name` 和 `description` 列，同样在 `CrmTranslations.xml` 中维护。

#### 4.2.4 SiteMap

SiteMap 导航项的 `Title` / `Description` 也通过 translations 导入，对应 `sitemap` 记录的相关列。

#### 4.2.5 App Action 按钮

App Action 的 `label` / `tooltip` 也通过 translations 导入，对应 `appaction` 记录的相关列。

#### 4.2.6 批量导入的替代方式

如果 D365 UI 的 Export/Import Translations 操作不便，也可以在本地编辑 `customizations.xml`：

1. 导出 `entity_YYYYMMDD_peter_trans` Solution ZIP。
2. 修改 `customizations.xml` 中各组件的 `LocalizedNames` / `Descriptions` 节点。
3. 重新压缩并导入 Solution。

但 **推荐优先使用 translations 导入**，因为 Solution 导入会触发更严格的依赖校验，可能影响其他组件。

#### 4.3.3 改造 JS 读取语言包

所有自定义 JS 统一通过 helper 读取（如果没有现成 helper，新增一个 `mcs_language_helper.js`）：

```javascript
var LanguageHelper = LanguageHelper || {};

LanguageHelper._cache = LanguageHelper._cache || {};

LanguageHelper.loadLanguagePack = function (callback) {
    var langId = Xrm.Utility.getGlobalContext().userSettings.languageId;
    var langCode = langId === 1033 ? "1033" : "2052";
    // 测试阶段使用 ms_languagefile_credit_test_<LCID>
    // 验证通过后改为 ms_languagefile_<LCID>
    var webResourceName = "ms_languagefile_credit_test_" + langCode;

    if (LanguageHelper._cache[webResourceName]) {
        if (callback) callback(LanguageHelper._cache[webResourceName]);
        return;
    }

    var req = new XMLHttpRequest();
    req.open("GET", Xrm.Utility.getGlobalContext().getClientUrl() + "/WebResources/" + webResourceName, true);
    req.setRequestHeader("Accept", "application/json");
    req.onreadystatechange = function () {
        if (req.readyState === 4 && req.status === 200) {
            try {
                LanguageHelper._cache[webResourceName] = JSON.parse(req.responseText);
                if (callback) callback(LanguageHelper._cache[webResourceName]);
            } catch (e) {
                console.error("加载语言包失败:", e);
                if (callback) callback({});
            }
        }
    };
    req.send();
};

LanguageHelper.getLabel = function (key) {
    var langId = Xrm.Utility.getGlobalContext().userSettings.languageId;
    var langCode = langId === 1033 ? "1033" : "2052";
    // 测试阶段使用 ms_languagefile_credit_test_<LCID>
    // 验证通过后改为 ms_languagefile_<LCID>
    var webResourceName = "ms_languagefile_credit_test_" + langCode;
    var dict = LanguageHelper._cache[webResourceName];
    return dict && dict[key] ? dict[key] : key;
};
```

使用示例：

```javascript
Xrm.Utility.alertDialog(LanguageHelper.getLabel("CreditRecord_NextStepConfirm"));
```

> 注意：
> 1. 每个语言包 WebResource 的完整名称在 D365 中可能包含 GUID；但 `/WebResources/<逻辑名>` 接口通常支持按逻辑名访问。如不行，需先查询实际名称。
> 2. HTML 页面同样通过上述 helper 加载语言包，再渲染文本。
> 3. 语言包更新后需发布 `McsWebResource` Solution。
> 4. 生产环境推荐将 `mcs_language_helper.js` 设为窗体依赖库（`formLibraries` 中放在业务脚本之前），实验阶段为减少窗体修改，可先通过同步 `XMLHttpRequest` 在业务脚本顶部动态加载 helper。

## 6. 工具代码改造示例

### 6.1 `LabelHelper` 新增重载

> **重要经验**：D365 组织基础语言为中文（2052）时，`Label` 的第一个 `LocalizedLabel` 必须是基础语言（2052），否则英文标签无法正确保存。

```csharp
// D365ToolCommon/Metadata/LabelHelper.cs
public static Label Create(string zhCN, string enUS)
{
    return Create(new Dictionary<int, string>
    {
        [2052] = zhCN,
        [1033] = enUS
    });
}

public static Label Create(Dictionary<int, string> translations)
{
    if (translations == null || translations.Count == 0) return new Label();

    var labels = translations
        .Where(t => !string.IsNullOrWhiteSpace(t.Value))
        .Select(t => new LocalizedLabel(t.Value, t.Key))
        .ToArray();

    if (labels.Length == 0) return new Label();

    return new Label(labels[0], labels.Skip(1).ToArray());
}
```

**用途**：
- 新实体/新字段创建时，一次性写入中英文双语 Label。
- 本地脚本生成 `CrmTranslations.xml` 或检查翻译完整性时构造 Label 对象。
- **禁止**用于直接更新 DEV1/UAT/生产已有组件的 Label。

### 6.2 本地辅助脚本（可选）

可以写一些本地脚本辅助处理 `CrmTranslations.xml`：

- 从翻译总表生成 `CrmTranslations.xml` 的英文列。
- 检查 `customizations.xml` 中是否有组件缺少 `LocalizedNames`。
- 对比两个环境的 translations 差异。

这些脚本只操作本地文件，不调用 D365 API。

## 8. 风险与红线

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 批量更新 Label 后，UAT/生产已有数据依赖显示名 | 视图/报表/集成可能显示异常 | 先在 DEV1 全量验证，确认英文显示名业务可接受 |

| 前端语言包缓存 | 用户浏览器可能读取旧 JS | 更新 WebResource 后发布并建议用户清缓存 |
| 多语言 Label 只更新 2052 没更新 1033 | 英文用户仍看到中文 | 用 `check-labels` 命令自动化检查 |

- 🚫 **UAT/生产元数据变更必须通过 n8n Release Tool / Solution 发布**，严禁直接操作。
- 🚫 **Git 提交必须用户明确说"提交"或"推送"** 才能执行。
- 🚫 **所有元数据翻译（实体/字段/选项集/表单/视图/SiteMap/AppAction label）必须通过 Solution 导入 translations 完成**，禁止通过 SDK/API 直接写 `LocalizedLabel`。
