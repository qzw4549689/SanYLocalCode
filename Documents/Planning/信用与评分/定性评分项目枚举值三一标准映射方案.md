# 定性评分项目枚举值三一标准映射方案

> **方案编号**：待分配（建议关联 F2.x 评分项目管理 / F4.x 信用分计算）  
> **状态**：待实施  
> **记录时间**：2026-07-01  
> **决策**：采用方案 B（配置化映射），把 Coface 原始值 → 三一标准编码的映射关系维护在 `mcs_credititem_value` 基础数据中，代码通过查表映射，避免硬编码。

---

## 1. 背景与问题

当前 `mcs_credititem_value`（定性评分项目枚举值）中国别风险按 Coface 原始编码维护：

- A1、A2 → 低风险
- A3、A4 → 中风险
- B、C、D、E → 高风险
- O → 缺失

这导致前端 `mcs_customer_tag` 表单的复核定性指标 Lookup 下拉出现重复显示（两个"低风险"、两个"中风险"、四个"高风险"）。

PRD 要求以三一标准为基础，国别/行业风险统一为四级：

- L：低风险
- M：中风险
- H：高风险
- O：缺失

标签取数仍以 Coface 编码（A1/A2…、1/2/3/4）去取，但前端展示和评分卡匹配都应使用三一标准。

---

## 2. 目标

1. 前端下拉只显示 4 条不重复的三一标准选项。
2. Coface API 返回原始值后，Plugin 自动映射到三一标准编码保存。
3. 评分卡配置和信用分计算统一按 L/M/H/O 匹配。
4. 映射关系可配置化，后续调整无需改代码发版。

---

## 3. 数据模型设计

### 3.1 新增字段

在 `mcs_credititem_value` 实体新增字段：

| 字段名 | 逻辑名 | 类型 | 长度 | 用途 |
|---|---|---|---|---|
| Coface 原始值 | `mcs_cofacevalue` | 字符串（nvarchar） | 255 | 存储 Coface 原始值，多个值用英文逗号分隔 |

### 3.2 国别风险（CountryRisk）

| `mcs_listvalue`（三一编码） | `mcs_listname`（显示名） | `mcs_cofacevalue`（Coface 原始值） |
|---|---|---|
| L | 低风险 | A1,A2 |
| M | 中风险 | A3,A4 |
| H | 高风险 | C,D,E（禅道#2190，2026-09-08 起；原 B,C,D,E，B 移入中风险 A3,A4,B） |
| O | 缺失 | O |

### 3.3 行业风险（SectorRisk）

| `mcs_listvalue`（三一编码） | `mcs_listname`（显示名） | `mcs_cofacevalue`（Coface 原始值） |
|---|---|---|
| L | 低风险 | 1 |
| M | 中风险 | 2 |
| H | 高风险 | 3,4 |
| O | 缺失 | O |

> 其他定性项目（ExternalRating、BigAccount、Sectors、DealerRating 等）如无需三一 ↔ Coface 映射，`mcs_cofacevalue` 留空即可。

## 4. 代码改动清单

### 4.1 新增 `mcs_credititem_value.mcs_cofacevalue` 字段

- 使用 `D365ToolCommon.Metadata.MetadataFieldService` 或 `MetadataTool` 已有公共方法创建字段。
- 遵守 AGENTS.md 红线：禁止直接调用 SDK 原生 `CreateAttributeRequest`。

### 4.2 `CofaceQualitativeMappingHelper.cs`

新增方法 `GetSanyValueByCofaceValue`：

```csharp
/// <summary>
/// 根据评分项目编码 + Coface 原始值，查询对应的三一标准编码（mcs_listvalue）
/// </summary>
public static string GetSanyValueByCofaceValue(
    IOrganizationService service,
    ITracingService tracer,
    string itemCode,
    string cofaceValue)
{
    if (string.IsNullOrWhiteSpace(cofaceValue) || string.IsNullOrWhiteSpace(itemCode) || service == null)
        return "O";

    try
    {
        // 1. 查评分项目 ID
        var itemQuery = new QueryExpression("mcs_credit_items")
        {
            ColumnSet = new ColumnSet("mcs_credit_itemsid"),
            Criteria = new FilterExpression
            {
                Conditions = { new ConditionExpression("mcs_credit_itemsno", ConditionOperator.Equal, itemCode) }
            },
            TopCount = 1
        };
        var item = service.RetrieveMultiple(itemQuery).Entities.FirstOrDefault();
        if (item == null) return cofaceValue;

        // 2. 查该评分项目下所有枚举值
        var query = new QueryExpression("mcs_credititem_value")
        {
            ColumnSet = new ColumnSet("mcs_listvalue", "mcs_cofacevalue"),
            Criteria = new FilterExpression
            {
                Conditions = { new ConditionExpression("mcs_credititemno", ConditionOperator.Equal, item.Id) }
            }
        };

        var records = service.RetrieveMultiple(query).Entities;
        foreach (var record in records)
        {
            var cofaceMapping = record.GetAttributeValue<string>("mcs_cofacevalue") ?? "";
            var values = cofaceMapping.Split(new[] { ',' }, StringSplitOptions.RemoveEmptyEntries)
                                      .Select(v => v.Trim())
                                      .ToList();
            if (values.Contains(cofaceValue, StringComparer.OrdinalIgnoreCase))
            {
                return record.GetAttributeValue<string>("mcs_listvalue") ?? cofaceValue;
            }
        }

        tracer.Trace($"未找到 {itemCode}/{cofaceValue} 的映射，返回原值");
        return cofaceValue;
    }
    catch (Exception ex)
    {
        tracer.Trace($"查询映射异常 [{itemCode}/{cofaceValue}]: {ex.Message}");
        return cofaceValue;
    }
}
```

`GetDisplayName` 保持不变，仍按 `itemCode + mcs_listvalue` 查 `mcs_listname`。

### 4.3 `CofaceDataSyncPlugin.cs`

修改 `UpdateTagValue` 的定性分支：

```csharp
string rawValue = value?.ToString() ?? "O";
string sanyValue = CofaceQualitativeMappingHelper.GetSanyValueByCofaceValue(service, tracer, itemCode, rawValue);
string displayValue = CofaceQualitativeMappingHelper.GetDisplayName(service, tracer, itemCode, sanyValue);

updateTag["mcs_itemvalue1"] = sanyValue;       // L/M/H/O
updateTag["mcs_itemtxtvalue1"] = displayValue; // 低风险/中风险/高风险/缺失
```

`MapValueToDisplayName` 中的硬编码 switch 可保留作为兜底，或后续逐步清理。

### 4.4 `ScoreCalculator.cs`

当前用 `EntityReference.Name`（即主字段 `mcs_listname`）作为匹配值。改为 Retrieve 记录取 `mcs_listvalue`（L/M/H/O）：

```csharp
if (lvObj is EntityReference lvRef)
{
    var lvEnt = service.Retrieve("mcs_credititem_value", lvRef.Id, new ColumnSet("mcs_listvalue", "mcs_listname"));
    listValue = lvEnt.GetAttributeValue<string>("mcs_listvalue") ?? lvRef.Name ?? "";
}
```

### 4.5 前端 `mcs_credit_scoringcard.js`（可选优化）

`loadListValues` 显示文本可调整为：

```javascript
text: entity.mcs_listname + " (" + entity.mcs_listvalue + ")"
// 例如：低风险 (L)
```

`mcs_customer_tag.js` 不需要改动，因为 `mcs_credititem_value` 只剩 4 条记录，Lookup 下拉自然不重复。

## 5. 数据迁移步骤

1. **新增字段**：`mcs_credititem_value.mcs_cofacevalue`
2. **合并国别风险记录**：
   - 删除 A1/A2/A3/A4/B/C/D/E 8 条旧记录
   - 新建/更新为 L/M/H/O 4 条，填充 `mcs_cofacevalue`
3. **合并行业风险记录**：
   - 删除 1/2/3/4 旧记录
   - 新建/更新为 L/M/H/O 4 条，填充 `mcs_cofacevalue`
4. **重新配置评分卡**：
   - `mcs_credit_scoringcard.mcs_listvalue` 是 Lookup，旧记录删除后原有配置会失效
   - 需要把评分卡里国别风险、行业风险的行重新指向 L/M/H/O 记录
5. **迁移历史标签数据**：
   - 把 `mcs_customer_tag.mcs_itemvalue1` 中现有的 A1/A2/A3/A4/B/C/D/E、1/2/3/4 批量更新为 L/M/H/O
   - 或者在 `ScoreCalculator` 里加一个兼容层：如果 `tag.StringValue` 不是 L/M/H/O，先查 `mcs_credititem_value` 映射后再匹配

## 6. 风险与注意事项

| 风险 | 说明 | 应对措施 |
|---|---|---|
| 评分卡配置失效 | 删除旧 `mcs_credititem_value` 记录后，原有 `mcs_credit_scoringcard.mcs_listvalue` Lookup 会失效 | 实施前导出评分卡配置，实施后批量重新指向 |
| 历史标签数据不兼容 | 已生成的 `mcs_customer_tag.mjs_itemvalue1` 可能仍存 A1/A2 等旧值 | 批量迁移或在算分代码加兼容层 |
| 元数据创建红线 | AGENTS.md 要求必须使用 `D365ToolCommon` 或 `MetadataTool` 公共方法 | 禁止直接调用 SDK 原生 `CreateAttributeRequest` |
| 逗号分隔字段查询边界 | `mcs_cofacevalue` 用逗号分隔，需避免"A1"误匹配"A11" | 内存精确匹配（Split + Trim + Equals），不依赖 Like |
