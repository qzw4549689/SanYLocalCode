## 三、风险敞口 —— 两套公式并存，【⚠️ 待拍板】

### 816 公式（客户维度，原文）

> 交易风险敞口 = 客户签约占用 + 客户风险敞口 + 中信保净占用 + 合同风险赊销 − 客户授信池余额
> 其中：客户风险敞口 = 厂端授信净占用

**【⚠️ 疑似笔误，需张烽确认】**：展开后 = 签约占用 + **厂端净占用** + **信保净占用** + 合同风险赊销 − 池余额，而池余额本身 = 上浮限额 + 厂端额度 − **厂端净占用 − 信保净占用**，净占用一正一负**出现两次、正好抵消**，等价于「签约占用 + 合同风险赊销 − 池总额」。请确认本意是：
- (a) 笔误，本意 = 签约占用 + 合同风险赊销 − 池总额（即净占用不应重复出现）；
- (b) 池余额项应为池总额（不扣净占用），公式其他项不变；
- (c) 其他本意。

### 1641 公式（合同维度，已上 UAT，我方接口服务合同评审）

> A 类（厂端/信保）风险敞口 = 合同签约占用 + 厂端已用余额 + 合同风险赊销 − 厂端授信额度 − 中信保有效限额**余额**（T+1 动态余额，无上浮）
> B 类（外部融资）风险敞口 = 合同风险赊销 − 融资授信金额

### 讨论路径（建议开会按此过）

1. 先确认「合同评审时看的敞口」（1641）与「客户监控看的敞口」（816）**是不是同一个数**；
2. 是同一个数 → 1641 按 816 改公式（**破坏性变更，已上 UAT，需提前通知合同模块**，他们可能在联调）；不是同一个数 → 写清各自定义与使用场景，避免混用；

4. 中信保基数统一为「上浮限额 − CRM 净占用」，T+1 余额降级为对账项。
