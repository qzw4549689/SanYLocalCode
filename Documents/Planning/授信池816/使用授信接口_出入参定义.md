# 使用授信接口（mcs_recordCreditDetail）— 出入参与场景定义

> 来源：飞书表格《营销风控接口》 https://rs2flu7c17.work.sany.com.cn/sheets/shtk5GPWvgI3Mmsjzh73DEvfF8d

## 一、接口清单（全表最终只保留 2 个接口）

| 接口名称 | Custom API 唯一名 | 接口形态 | 备注 |
|---|---|---|---|
| 查询授信 API | `mcs_queryCreditBalance` | D365 Custom API（D365 内部接口） | 主要是给合同模块查询使用 |
| 使用授信 API | `mcs_recordCreditDetail` | D365 Custom API（D365 内部接口） | 主要是给交货单，订单，解款记录使用 |

## 二、使用授信入参

| 参数名 | 类型 | 必填 | 说明 |
|---|---|---|---|
| mcs_accountid | String | 是 | 客户编码（SAP客户代码），按客户主数据 mcs_sapnumber 匹配 |
| mcs_creditType | String | 否 | 授信类型：FACTORY=厂端授信 / SINOSURE=中信保授信 |
| mcs_usebalanceUSD | Decimal | 是 | 使用或者释放的授信金额美元 |
| mcs_usebalanceCNY | Decimal | 是 | 使用或者释放的授信金额人民币 |
| mcs_proccess | String | 是 | 1厂端授信模型计算 / 2厂端授信限额额度申请 / 3厂端授信限额归零调整 / 4提交合同评审 / 5合同变更信用类别 / 6合同取消 / 7订单执行验收 / 8订单变更信用类别 / 9回款解款 / 10订单退货 / 11订单取消 / 12其他（保留字段）。1-2 由客户厂端授信管理PRD覆盖相关台账记录；3-8 由授信额度动态运用管理PRD覆盖管理 |
| mcs_adjust | String | 是 | 额度调整动作：1=初始化 / 3=占用 / 4=释放 |
| mcs_contractid | String | 条件必填 | 合同编码（mcs_contract.mcs_name）；环节 ≥3 时必填 |
| mcs_orderid | String | 条件必填 | 订单编码（mcs_order.mcs_name）；环节 6-10 时必填 |
| mcs_delivery ordid | String | 条件必填 | 发货单编码（参数名含空格，疑笔误，应为 mcs_deliveryordid，待确认） |
| mcs_settle_id | String | 条件必填 | 解款单明细guid |
| mcs_settle_no | String | 条件必填 | 解款单号 |

入参表 E 列（事件枚举）：发货单推出 / 发货单取消 / 退货订单 / 退货订单取消 / A解款 / B解款红冲

## 三、使用授信返回

| 参数名 | 类型 | 说明 |
|---|---|---|
| mcs_accountid | String | 客户编码（请求参数原样回显） |
| mcs_usebalance | Decimal | 调整厂端授信金额USD（请求参数原样回显） |
| mcs_proccess | String | 流程环节（请求参数原样回显） |
| mcs_adjust | String | 额度调整动作（请求参数原样回显） |
| mcs_contractid | String | 合同编码（请求参数原样回显） |
| mcs_orderid | String | 订单编码（请求参数原样回显） |
| mcs_usedbalance | Decimal | 实际调整厂端授信余额USD，失败时 0.00 |
| mcs_sellerbalance | Decimal | 调整后厂端授信余额USD（允许负数，表示超额） |
| mcs_usedflag | String | 是否调整成功：1 成功 / 0 失败 |
| mcs_recordid | String | 台账编号（FCR+YYYYMMDD+5位序列号，成功时填入） |
| mcs_failreason | String | 使用失败原因（失败时填入） |

## 四、使用授信场景与调用细节

**大前提条件：**
1. 订单创建日期是 2026-09-03 之后；
2. 订单成交条件是赊销（中信保赊销、厂端授信）。

| 模块 | 事件 | 前提条件 | 类型 | 占用/释放金额 | 触发状态（业务） | 触发状态（IT） | 说明 |
|---|---|---|---|---|---|---|---|
| 发货单 | 发货单推出 | | 占用 | max(0, 交货单对应订单金额 − 订单累计解款金额) | 过账 | 数据从SAP同步至CRM，交付状态：已发货；SAP交货单过账调用接口 | |
| 发货单 | 发货单取消 | 取消的发货单有占用授信 | 释放 | max(0, 交货单对应订单金额 − 订单累计解款金额) | 取消过账 | 数据从SAP同步至CRM，交付状态：已取消；SAP交货单过账调用接口 | |
| 订单 | 退货订单 | 对应订单有推交货单 | 释放 | max(0, 交货单对应订单金额 − 订单累计解款金额) | 入库完成（过账） | | 退货订单的退货过账从SAP同步至CRM，且状态是【已发货】 |
| 订单 | 退货订单取消 | 对应退货订单有释放授信 | 占用 | max(0, 交货单对应订单金额 − 订单累计解款金额) | 入库完成（过账） | | CRM里取消退货订单，并请求ERP取消，待接口返回成功，则可释放授信 |
| 财务 | 解款 | 对应订单有推交货单 | 释放 | ΔS（解款金额） | SAP生成财务凭证 | | 解款SAP生成财务凭证后同步至CRM |
| 财务 | 解款红冲 | 对应解款有释放授信 | 占用 | ΔS（解款红冲金额） | SAP生成红冲财务凭证 | | 解款红冲SAP生成财务凭证后同步至CRM |

> 金额全部由调用方算好传入（哑记账），我方不计算 max(0, A−R−S)。
