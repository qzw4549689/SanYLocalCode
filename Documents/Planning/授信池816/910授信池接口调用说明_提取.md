## 页签1：接口概览

| 项目 | 内容 |
|------|------|
| 方案背景 | 营销风控授信额度确认方案（816方案）：客户授信池 = 厂端授信 + 中信保授信，双池统一占用/释放管理 |
| 接口形态 | SanyD365.Main Application 层服务类（C# 接口注入调用，同进程直连 D365）。接口：IAppCreditPoolService（[Injection] 自动注册，无需改启动配置） |
| 代码位置（uat 分支） | Service/SanyD365.Main/Application/Sales/CreditPool/IAppCreditPoolService.cs + AppCreditPoolService.cs；Service/SanyD365.Main/DTO/Sales/CreditPool/CreditPoolDtos.cs |
| 方法清单 | ① RecordCreditDetail：使用授信（占用/释放/初始化，哑记账）；② QueryCreditBalance：查询授信（客户维度，传合同附带合同授信金额） |
| 调用方 | 合同模块（经 ClientAPI 进程内注入调用）、交货单/订单/解款同步等 D365 内部模块（构造函数注入 IAppCreditPoolService 直接调用） |
| 小数位数（统一） | 全部金额字段统一两位小数（0.00）：DTO decimal 入参/出参均按两位小数处理；台账/额度落库字段均为 Money precision=2；CNY=USD×汇率后四舍五入保留两位。汇率取 transactioncurrency.exchangerate，decimal precision=12（当前 CNY=7.00305） |
| 生效方式 | 代码合并到 uat 分支后管道自动部署，无其他发布动作 |
| 核心原则 | 哑记账：金额（含 max(0, 订单金额−累计解款)、ΔS 解款金额）全部由调用方算好传入，本服务不做金额计算，只校验 + 幂等保存台账 + 更新余额 |
| 大前提（调用方保证） | 1. 订单创建日期是 2026-09-10 之后（继顺已做成可配置）；2. 合同成交条件是融资、赊销（中信保赊销、厂端授信）才会显示授信相关信息；如果是融资只展示融资金额、融资余额、客户签约占用 |
| 数据落点 | 台账统一写 mcs_fca_records；厂端余额走 mcs_fca_quota（不变式：授信额度=余额+占用）；中信保不落余额库，净占用由台账实时聚合 |
| ⚠️ 重要变更（v2） | 原 D365 Custom API（mcs_recordCreditDetail / mcs_queryCreditBalance）方案已废弃，不再对外提供；逻辑全部下沉到本服务类，契约（业务字段）保持不变 |
| 文档版本 | v2.3（2026-08-26，北京时间）：三个可用标志按对齐表字段定义返回原始类型（融资bool/中信保int quotastate/基线int isactive） |

## 页签2：使用授信-入参（RecordCreditDetailRequest）

| DTO 属性 | 类型 | 必填 | 说明 |
|---------|------|------|------|
| AccountCode | string | 是 | 客户编码（SAP客户代码），按客户主数据 mcs_sapnumber 匹配 |
| CreditType | string | 否 | 授信类型：1:FACTORY=厂端授信 / 2:SINOSURE=中信保授信；不传默认 FACTORY。推交货单时不传，后续都要从订单获取授信类型传过来 |
| UseBalanceUSD | decimal（两位小数） | 是 | 使用或者释放的授信金额美元（≥0） |
| UseBalanceCNY | decimal（两位小数） | 是 | 使用或者释放的授信金额人民币（≥0，快照保存） |
| Proccess | string | 是 | 流程环节 1-12：1厂端授信模型计算 / 2厂端授信限额额度申请 / 3厂端授信限额归零调整 / 4提交合同评审 / 5合同变更信用类别 / 6合同取消 / 7订单执行验收 / 8订单变更信用类别 / 9回款解款 / 10订单退货 / 11订单取消 / 12其他（保留）。1-2 由客户厂端授信管理PRD覆盖；3-8 由授信额度动态运用管理PRD覆盖 |
| Adjust | string | 是 | 额度调整动作：1=初始化 / 3=占用 / 4=释放。初始化仅限环节 1/2，且仅 FACTORY 支持 |
| ContractCode | string | 条件必填 | 合同编码（mcs_contract.mcs_name）；环节 ≥3 时必填 |
| OrderCode | string | 条件必填 | 订单编码（mcs_order.mcs_name）；环节 6-10 时必填 |
| DeliveryNo | string | 条件必填 | 发货单编码；环节 7（订单执行验收）必填 |
| SettleId | string | 条件必填 | 解款单明细guid；环节 9（回款解款）必填，解款类幂等键 |
| SettleNo | string | 条件必填 | 解款单号；环节 9（回款解款）必填 |

（页签中「继顺」列标注：AccountCode/UseBalanceUSD/UseBalanceCNY/Proccess/Adjust「传了」，CreditType「没传」；继顺侧环节清单：厂端授信模型计算/厂端授信限额额度申请/厂端授信限额归零调整/发货单推出/发货单取消/退货订单/退货订单取消/解款/解款红冲）

## 页签3：使用授信-返回（RecordCreditDetailResult）

| DTO 属性 | 类型 | 说明 |
|---------|------|------|
| UsedFlag | string | 是否调整成功：1 成功 / 0 失败 |
| UsedBalance | decimal（两位小数） | 实际调整授信金额USD，失败时 0.00 |
| SellerBalance | decimal（两位小数） | 调整后授信余额USD（允许负数，表示超额）。FACTORY=厂端授信余额；SINOSURE=信保上浮余额（=上浮限额−净占用） |
| RecordId | string | 台账编号（FCR+YYYYMMDD+5位序列号，成功时填入） |
| FailReason | string | 使用失败原因（失败时填入） |
| IdempotentReplay | bool | 是否幂等重放（true=重复调用，返回的是首次处理结果，未重复记账） |
| CreditType | string | 授信类型：1:FACTORY=厂端授信 / 2:SINOSURE=中信保授信。Case1：推交货单时由本服务判断中信保还是厂端（根据中信保批复限额上浮余额>占用金额判断）并返回结果；Case2：其他场景由调用方传授信类别，不传则厂端授信保底（带问号，待拍板） |

## 页签4：使用授信-幂等与场景

| 项目 | 内容 |
|------|------|
| 幂等机制 | 重复调用不重复记账，直接返回首次处理结果（UsedFlag=1 + 首次台账编号 + IdempotentReplay=true） |
| 幂等键规则 | 解款类：SettleId（解款明细guid，天然唯一）；发货类：发货单编码+环节+动作；兜底：合同编码+订单编码+环节+动作+金额USD |
| 场景1 发货单推出 | 模块=发货单，事件=占用，金额=max(0, 交货单对应订单金额−订单累计解款金额)。触发：SAP交货单过账（数据同步CRM，交付状态=已发货）。调用：Proccess=7, Adjust=3，传合同+订单+发货单编码。授信类型：先查询客户中信保批复限额上浮余额是否足够，够则用中信保授信，不够则用厂端授信（TBD） |
| 场景2 发货单取消 | 模块=发货单，事件=释放（前提：取消的发货单有占用授信）。触发：取消过账。调用：Proccess=7, Adjust=4，传合同+订单+发货单编码。授信类型：与之前占用时使用的类型保持一致（在台账表按交货单查询占用的类型，按创建日期最新排前取第一条） |
| 场景3 退货订单 | 模块=订单，事件=释放（前提：对应订单有推交货单）。触发：退货过账从SAP同步至CRM且状态=已发货。调用：Proccess=10, Adjust=4，传合同+订单。授信类型：与之前占用保持一致（根据退货订单关联的原订单最新交货单占用的类型） |
| 场景4 退货订单取消 | 模块=订单，事件=占用（前提：对应退货订单有释放授信）。调用：Proccess=10, Adjust=3，传合同+订单。授信类型：与之前占用保持一致 |
| 场景5 解款 | 模块=财务，事件=释放，金额=ΔS（解款金额）。触发：SAP生成财务凭证后同步至CRM。调用：Proccess=9, Adjust=4，传合同+订单+解款单号+解款明细guid。授信类型：与之前占用保持一致 |
| 场景6 解款红冲 | 模块=财务，事件=占用，金额=ΔS（解款红冲金额）。触发：SAP生成红冲财务凭证后同步至CRM。调用：Proccess=9, Adjust=3，传合同+订单+解款单号+解款明细guid。授信类型：与之前占用保持一致 |
| 超额处理 | 余额允许负数（表示超额），不拦截；释放金额超过累计占用时，厂端占用金额字段按 0 兜底（余额照常累加） |
| 失败处理 | 入参校验失败/客户、合同、订单找不到/额度不存在或未生效：UsedFlag=0 + FailReason 具体原因，不写台账、额度自动回滚 |

## 页签4b：使用授信场景与调用细节（2026-09-07 新增页签）

大前提条件：1.交货单、退货订单对应的常规订单创建日期是 2026-09-10 之后；2.订单成交条件是赊销（中信保赊销、厂端授信）。

| 模块 | 事件 | 前提条件 | 类型 | 占用/释放金额 | 触发状态（业务） | 触发状态（IT） | 说明 |
|---|---|---|---|---|---|---|---|
| 发货单 | 发货单推出 | | 占用 | max(0, 交货单对应订单金额 − 订单累计解款金额) | 过账 | 常规订单对应的发货单从SAP同步至CRM，交付状态：已发货 | |
| 发货单 | 发货单冲消 | 取消的发货单有占用授信 | 释放 | max(0, 交货单对应订单金额 − 订单累计解款金额) | 取消过账 | 交付状态：从已发货变成未发货 | CRM先查询交货单状态是已发货；SAP同步过来的交货单状态是未发货，两条件同时满足 |
| 订单 | 退货订单 | 对应订单有推交货单 | 释放 | max(0, 交货单对应订单金额 − 订单累计解款金额) | 入库完成（过账） | 退货订单对应的发货单从SAP同步至CRM，且发货单状态是已发货 | |
| 订单 | 退货订单取消 | 对应退货订单有释放授信 | 占用 | max(0, 交货单对应订单金额 − 订单累计解款金额) | 入库完成（过账） | 交付状态：从已发货变成未发货 | 同发货单冲消两条件 |
| 财务 | 解款 | 对应订单有推交货单 | 释放 | ΔS（解款金额） | SAP生成财务凭证 | 解款SAP生成财务凭证后同步成功至CRM | |
| 财务 | 解款红冲 | 对应解款有释放授信 | 占用 | ΔS（解款红冲金额） | SAP生成红冲财务凭证 | 解款红冲SAP生成财务凭证后同步至CRM | |

## 页签6：查询授信-返回（QueryCreditBalanceResult）

| DTO 属性 | 类型 | 说明 | 取数来源 | 对应合同页面字段 |
|---------|------|------|---------|----------------|
| CreditLimitUSD / CreditLimitCNY | decimal（两位小数） | 融资金额（传了合同编码才查） | 合同实体授信金额字段（字段未落地，暂返回 0） | 融资金额 / 融资金额余额（如果合同是赊销这个应该都是0） |
| SinosureLimitUSD / SinosureLimitCNY | decimal（两位小数） | 中信保批复限额 | mcs_approvedquota 有效记录（quotastate=1+生效失效区间）按客户汇总，T+1 同步；CNY 按汇率实时计算 | 中信保限额（只有赊销支付才显示） |
| SinosureBalanceUSD / SinosureBalanceCNY | decimal（两位小数） | 中信保批复限额余额 | mcs_approvedquota.mcs_quotabalance 汇总（中信保 T+1 动态余额，仅参考） | |
| SinosureUpliftLimitUSD / SinosureUpliftLimitCNY | decimal（两位小数） | 中信保批复限额上浮限额 | 每次计算：批复限额 + min(批复限额×0.5, 8M)（即 min(批复限额×1.5, 批复限额+8M)）；排除国家不上浮（=批复限额）；系数/封顶/国家清单走配置 SinosureUpliftConfig | |
| SinosureNetUsedUSD / SinosureNetUsedCNY | decimal（两位小数） | 中信保净占用额度 | 每次计算：根据客户编码到数据湖查询中信保授信占用、中信保授信释放；净占用=占用−释放 | |
| SinosureUpliftBalanceUSD / SinosureUpliftBalanceCNY | decimal（两位小数） | 中信保批复限额上浮余额 | 每次计算：上浮限额 − 中信保净占用额度 | 中信保限额净余额（只有赊销支付才显示） |
| FactoryLimitUSD / FactoryLimitCNY | decimal（两位小数） | 客户交易基线额度 | mcs_fca_quota.mcs_sellergrant（厂端授信额度） | 安全交易基线（只有赊销支付才显示） |
| RiskExposureUSD / RiskExposureCNY | decimal（两位小数） | 客户风险敞口 | 每次计算：数据湖查询厂端授信占用、厂端授信释放；风险敞口=占用−释放 | 客户风险敞口（只有赊销支付才显示） |
| FactoryBalanceUSD / FactoryBalanceCNY | decimal（两位小数） | 客户交易基线余额 | 每次计算：客户交易基线额度 − 客户风险敞口 | 安全交易基线余额（只有赊销支付才显示） |
| SigningOccupyUSD / SigningOccupyCNY | decimal（两位小数） | 客户签约占用 | 每次计算：数据湖查询客户签约占用 | 客户签约占用（全部都看） |
| FinancingAvailable | bool | 融资是否可用（对齐 mcs_fsm_data.mcs_is_valid，Boolean） | 存在 mcs_is_valid=true 的融资管理记录（按客户编码匹配）=true | |
| SinosureAvailable | int | 中信保是否可用（对齐 mcs_approvedquota.mcs_quotastate 原始值） | 1=有效（存在 quotastate=1 且在生效/失效区间的批复限额记录）/ 2=预批（无有效但有预批记录）/ 0=无效（无记录） | |
| FactoryBaselineAvailable | int | 安全交易基线是否可用（对齐 mcs_fca_quota.mcs_isactive 原始值） | 1=是（额度记录生效）/ 0=否 | |
| UsedFlag | string | 是否查询成功：1 成功 / 0 失败 | — | |
| FailReason | string | 查询失败原因（客户/合同找不到等） | — | |

合同模块自行计算项（接口不返回）：
- 合同风险赊销 = 赊销合同金额 − 合同使用现款部分额度
- 交易风险敞口 = 客户签约占用（接口）+ 本次合同风险赊销（合同自己算）−（中信保批复限额上浮余额 + 客户交易基线余额）
- 签约超限标记 = 交易风险敞口 > 0 ？超限 : 不超限

## 页签7：配置与示例

| 调用示例（使用授信） | 构造函数注入 IAppCreditPoolService；RecordCreditDetail(new RecordCreditDetailRequest { AccountCode="0210000680", CreditType="FACTORY", UseBalanceUSD=30000m, UseBalanceCNY=213000m, Proccess="7", Adjust="3", ContractCode="HT2026001", OrderCode="SO2026001", DeliveryNo="DEL2026001" })；result.UsedFlag=="1" 成功；result.IdempotentReplay==true 幂等重放 |
