## 二、阶段一：信保限额取值 + 上浮计算基础层（现在可做，不依赖 PRD）

> 理由：① 中信保取值落点已实查明（`mcs_approvedquota`，T+1 同步，quotastate=1+生效失效区间）；② 上浮规则已定调"以 816 最新版为准、全参数化"；③ 纯新增代码，不动任何旧逻辑，PRD 后续修订只需改配置不改代码。

### 1.1 上浮配置（ms_systemconfiguration JSON）

- **新增配置模型**：`SinosureCreditPoolConfig`（复刻 `CofaceCountryConfig` + `CofaceCountryConfigHelper` 成熟模式）：
  - `floatCoefficient`（默认 1.5）、`floatCapUsd`（默认 8000000）
  - `noFloatCountryCodes`（不上浮国家清单，Q5 确认前先空数组占位，配置化随时填）
  - `quotaFilters`（批复限额记录的过滤维度可配：applygenre / paymode 白名单，应对 Q4 口径调整）
- **Helper**：`SinosureCreditPoolConfigHelper.GetConfig(service)`，配置缺失→默认值不阻塞，JSON 错→抛 `InvalidPluginExecutionException`。
- **配置数据登记**：同步登记《D365配置数据清单.md》+《上线核对清单》第 4 章（红线：开发过程同步评估发布清单影响）。

### 1.2 中信保批复限额查询服务

- **新增** `SinosureQuotaQueryService`：
  - 客户 → 买方代码：`mcs_customermasterdata` → `mcs_sinosure_buyercode`（买方代码主数据，带客户 Lookup）；`*/*` 通用买方代码先排除并记 Trace（Q4）。
  - 买方代码 → `mcs_approvedquota`：过滤 `mcs_quotastate=1`（有效）+ 当天在 `mcs_effectdatestr`/`mcs_lapsedatestr` 区间内 + 配置化 applygenre/paymode 过滤。
  - 汇总 `mcs_quotasum`（Decimal，批复限额）→ 官方限额；`mcs_quotabalance`（String，中信保 T+1 动态余额）仅作参考返回值+对账，**不参与池计算**（避免与 CRM 自记净占用重复扣减，摸底 §四.2 结论）。
  - 上浮限额 = `min(官方 × floatCoefficient, floatCapUsd)`，命中不上浮国家取官方原值；国家取自客户主数据国家字段。
- **参考先例**：`RiskExposure.Api/RiskExposureService.cs` 的 `GetSinosureBalance`（注意它取的是 quotabalance 且写死 applygenre=1/paymode=4，新服务改为取 quotasum + 过滤可配，**不动旧代码**，1641 接口行为不变）。

### 1.3 池查询 Custom API `mcs_QueryCreditPool`（草案版，可选）

- §8 接口清单 #2，查询类、无副作用，契约相对稳定：输入客户（SAP 编码），返回厂端额度/占用/余额（读 `mcs_fca_quota` 现成字段）+ 信保官方限额/上浮限额/参考余额 + 池总额/池余额（信保净占用在阶段二明细字段落地前先返回 null 或按 0，出参结构预留）。
- 是否阶段一就做，取决于 Q1 出参契约确认速度；不做则并入阶段三。

### 1.4 工程与合规动作

- **开发方式**：本地独立项目 `Code/Customizations/Plugins/CreditPool.Api/`（csproj 复刻 FactoryCredit.Api），本地编译 → DEV1 临时独立 Assembly 验证 → **测试结束第一时间 `unregister-assembly` 注销（红线）** → 用户授权后走 `sync-plugin-to-remote.py` 同步远程主项目 `SanyD365.D365ExtensionApi.Sales` → tx-windows 推分支 + PR → 用户合并 → 用合并后 uat 重编 → 更新 DEV1 主 Assembly → `CustomApiDeployer` 部署/重绑（五步模式，加 `McsCustomAPI`）。
- **DEV1 验证用例**：有批复限额客户（UAT 39 条 `mcs_approvedquota` 可参考造数）、无买方代码客户、上浮/不上浮国家、封顶边界（官方 6M→1.5 倍 9M 截到 8M）、多记录汇总。
- **新增组件登记**：Custom API 本体+参数+响应 → 主清单 `AllComponent_Peter_NoUAT`（红线）+ 看板发布清单登记（红线，不等端到端验证）；配置数据 → 《D365配置数据清单.md》。
- **测试证据**：`Backups/Tests/` 下按任务归置（红线）。

## 三、阶段二：台账/额度表字段扩展（Q1 字段清单确认后）

- **`mcs_fca_records` 新增字段**（以 PRD 终版为准，草案见实施方案 §2）：`credit_type`（FACTORY/SINOSURE）、`biz_type`（OCCUPY/RELEASE）、`source_type`（DELIVERY/CANCEL/RETURN/SETTLE/REDCHARGE）、`source_no`、`related_source_id`（自关联红冲溯源）、`order_no`/`delivery_no`、快照 `order_amount_A`/`return_amount_R`/`settle_amount_S`、`amountCNY`、`fx_rate`。选项集用局部选项集随实体走。
- **`mcs_fca_quota` 信保侧字段**：落点待 Q1（挂在 fca_quota 还是另建记录），字段名/口径以 PRD 为准。
- **幂等约束**：`source_type + source_no + biz_type` 建 Alternate Key——**工具无现成能力，需先向用户申请扩展 D365ToolCommon/MetadataTool 公共方法（Q6）**；申请未过则退化方案=插件内查重（性能略差，可接受）。
- **Definitions JSON 同步更新**（`Code/Tools/MetadataTool/Definitions/mcs_fca_records.json` 等）。
- **表单/视图**：台账表单加新字段分区、新增「授信池占用释放明细」视图；双语标签走 translations（翻译总表追加）。
- **合规**：字段随实体整体在主清单（rootcomponentbehavior=0，无需单独加）；发版包归属问用户（红线：导包改实体必须先问用哪个包）；实体发布用 `publish <实体>` 指定发布。

## 四、阶段三：占用/释放接口扩展（Q1 入参契约确认后）

- **定调**：优先轻量扩展 `mcs_AdjustFcaQuotaBalance`（哑记账天然吻合，未发 UAT 零调用无兼容包袱）；若新参数清单改动大，按同模式新建 `mcs_CreditPoolAdjust`，旧 API 不动。
- **改造点**（在 `FactoryCredit.Api/` 或新 `CreditPool.Api/`）：
  1. 新入参：`credit_type`/`source_type`/`source_no`/幂等键/快照 A·R·S/CNY/汇率（以 PRD 为准）；
  2. 幂等升级：从"仅占用动作查最新台账"升级为"幂等键查重、重复调用直接返回上次结果"（Alternate Key + 插件查重双保险）；
  3. 台账写新字段（新旧记录靠新字段区分，授予层插件写旧字段不动——字段分工约定不变：授予层只写额度字段、占用释放接口只写占用/余额字段）；
  4. 信保池余额更新（落点按阶段二结果）；
  5. 补偿回滚沿用现有 `RevertQuota`/`DeleteQuotaQuietly` 模式。
- **A4/A5 已并入本阶段**（2026-08-20 用户明确，不设独立接口）：816 IT 表发货事件动作=checkAndOccupy（校验+占用一体）——DELIVERY 占用时接口内部判定 credit_type（优先全额信保→全额厂端）+ 校验对应池余额，不足返回失败不记账，判定结果随出参返回供上游反写订单；预警线/特批 BPP 职责待 Q2。
- **查询接口**：`mcs_QueryCreditChangeDetail`（明细查询，对账用）契约简单可先做。
- **验证**：8 场景回归（复用阶段 2.17 的测试矩阵）+ 幂等重放 + 红冲溯源链。
- **合规**：接口文档更新《厂端授信余额调整API调用说明.md》或新写调用说明；看板发布清单更新既有项。

## 五、阶段四：A6 汇总计算 + 风险敞口（Q3 拍板后）

- 净占用聚合：FetchXML 按 `credit_type` 分组 ΣOCCUPY−ΣRELEASE；量大则落冗余字段+每日对账（与阶段五对账任务联动）。
- 风险敞口：按拍板结论执行三选一——1641 改公式（破坏性变更，已上 UAT，需提前跟合同模块打招呼）/ 两场景两公式写清定义分工 / 1641 废弃。
- **讨论材料已就绪**（实施方案 §6：两套精确公式对照+四个分歧点+816 公式净占用两次疑似笔误找张烽确认），本阶段只做落地。

## 六、阶段五：A7 报表 + A9 对账 + 上线切换

- 报表：池台账/明细 = D365 视图+高级查找（零代码）；已发货未投保清单 = `mcs_shipmentdeclare_applyinfo.mcs_ordernum` 与已发货订单比对出视图（Q7 归属确认后）。
- 对账：每日定时（Power Automate 或 ServiceJobs 控制台+计划任务，参照 `CreditRecordExpiration` 先例）：Σ明细 vs 余额冗余字段、CRM 净占用 vs `mcs_quotabalance`（T+1 参考）差异清单。
- 期初切换：中信保"签约未发货"占用明细梳理导入 `mcs_fca_records`（source_type=DELIVERY 期初标记），厂端无期初；导入后 Σ期初=业务确认在途占用总额核对；`mcs_AdjustFcaQuotaBalance` 未发 UAT 无切流问题。
