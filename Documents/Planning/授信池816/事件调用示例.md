# 816 授信池 — 5 类业务事件调用示例（给对方开发）

> 接口：授信池余额调整接口 `mcs_AdjustFcaQuotaBalance`（扩展后）
> 约定：金额恒正，方向由动作（mcs_adjust）表达；金额由调用方算好后传入，CRM 不重新计算；同一单据重复推送安全（幂等）。
> 示例客户：SAP 编码 0210000680；示例订单金额 A = 100,000 USD。

## 事件 1：发货单推出（占用，checkAndOccupy）

场景：订单 A=10 万，发货前已解款 S=3 万 → 调用方算得占用金额 = A − S = **7 万**。

```json
{
  "mcs_accountid": "0210000680",
  "mcs_usebalance": 70000,
  "mcs_adjust": "3",
  "mcs_orderid": "SO20260820001",
  "mcs_credit_type": "",                  // 可不传，接口内部判定：信保上浮余额≥7万→SINOSURE，否则厂端够→FACTORY
  "mcs_source_type": "DELIVERY",
  "mcs_source_no": "DN20260820001",
  "mcs_delivery_no": "DN20260820001",
  "mcs_order_amount_a": 100000,
  "mcs_return_amount_r": 0,
  "mcs_settle_amount_s": 30000,
  "mcs_biz_date": "2026-08-20"
}
```

结果：内部判定（例如信保够）→ 信保池 净占用 +7万、余额 −7万；写台账一条（credit_type=SINOSURE, biz_type=OCCUPY）；出参 `mcs_credit_type=SINOSURE` 返回供反写订单。
**余额不足**：返回 `mcs_usedflag=0` + `mcs_failreason`，不记账 → 上游阻断或走特批。
**重复推送**：返回首次结果 + `mcs_idempotent_replay=1`，不重复记账。

> 变体：无解款（S=0）→ 金额=10 万全额占用；全额解款（S=A）→ 不调用（先款后货不占池）。

## 事件 2：发货单取消（释放）

场景：上例 7 万占用的交货单整单取消，取消前无解款变化 → 释放金额 = A − S = **7 万**。

```json
{
  "mcs_accountid": "0210000680",
  "mcs_usebalance": 70000,
  "mcs_adjust": "4",
  "mcs_orderid": "SO20260820001",
  "mcs_credit_type": "SINOSURE",
  "mcs_source_type": "CANCEL",
  "mcs_source_no": "DN20260820001",
  "mcs_delivery_no": "DN20260820001",
  "mcs_order_amount_a": 100000,
  "mcs_return_amount_r": 100000,
  "mcs_settle_amount_s": 30000
}
```

结果：信保池 净占用 −7万、余额 +7万；台账一条（biz_type=RELEASE）。
**注意**：释放必须传 credit_type（与当初占用同池）；若当初占用是接口内部判定的，上游以反写到订单的类型为准。

## 事件 3：退货订单（释放）

与事件 2 相同，`mcs_source_type=RETURN`，`mcs_source_no`=退货单号，`mcs_delivery_no` 填原交货单号。释放金额=该单剩余占用 = max(0, A−S)，调用方算好。

## 事件 4：解款/认款（释放）

场景：交货后又收到结款 4 万（S：3万→7万）→ 释放金额 = ΔS = **4 万**。

```json
{
  "mcs_accountid": "0210000680",
  "mcs_usebalance": 40000,
  "mcs_adjust": "4",
  "mcs_orderid": "SO20260820001",
  "mcs_credit_type": "SINOSURE",
  "mcs_source_type": "SETTLE",
  "mcs_source_no": "ST20260821001",
  "mcs_order_amount_a": 100000,
  "mcs_return_amount_r": 0,
  "mcs_settle_amount_s": 70000
}
```

> 变体：交货前结款（无占用）→ 释放金额=0，**不调用**。

## 事件 5：解款红冲（重占）

场景：上例 4 万结款被红冲（S：7万→3万）→ 重新占用金额 = ΔS = **4 万**。

```json
{
  "mcs_accountid": "0210000680",
  "mcs_usebalance": 40000,
  "mcs_adjust": "3",
  "mcs_orderid": "SO20260821001",
  "mcs_credit_type": "SINOSURE",
  "mcs_source_type": "REDCHARGE",
  "mcs_source_no": "RC20260821001",
  "mcs_related_source_no": "ST20260821001",   // 必填：被红冲的原结款单号
  "mcs_order_amount_a": 100000,
  "mcs_return_amount_r": 0,
  "mcs_settle_amount_s": 30000
}
```

结果：信保池 净占用 +4万、余额 −4万；台账一条（biz_type=OCCUPY，`mcs_related_recordid` 指向原 SETTLE 台账）。
**红冲溯源失败**（找不到原结款台账）→ 返回失败不记账。

## 附：期初导入（上线切换一次性）

同事件 1 结构，`mcs_source_type=INITIAL`、`mcs_credit_type=SINOSURE`、金额为签约未发货占用额；不做余额校验（期初允许超上限入帐）。模板见《816授信池_期初占用明细导入模板.xlsx》。
