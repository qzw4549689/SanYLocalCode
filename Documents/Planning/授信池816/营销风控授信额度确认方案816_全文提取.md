## 一、一些共识点

### 1. 授信定义与层级

```
授信（总称）
├── 外部融资          ← 合同级，银行资金，不占客户授信池
└── 赊销             ← 客户级，公司赊账，占客户授信池
    ├── 厂端授信      ← 客户级，客户授信池，自担风险
    └── 中信保授信    ←  客户级，客户授信池，信保承保
```

### 2. 合同、订单、交货单模块

- 合同中有唯一的授信类型：外部融资、赊销（同时包含厂端授信和中信保授信）；只有合同和订单是赊销才会进入相关逻辑；
- 单个订单不混合使用厂端授信和中信保授信，订单使用哪种类型系统自动做判断（在推交货单的时候，确定类型并反写订单），优先全额使用中信保授信，如果额度不够，则全额使用厂端授信。
- 发货时没有信保额度，发货后中信保额度下来了，中信保批复限额上浮额度可用能覆盖订单赊销金额，将订单拉到"待投保清单中"，触发中信保出运投保订单（830这个版本来不及实现）

### 3. 客户授信池

- 系统中记录厂端授信总金额、厂端授信使用、释放明细。根据明细可计算出厂端授信使用总金额以及剩余金额。
- 系统中记录中信保授信总金额、中信保授信使用、释放明细。根据明细可计算出中信保授信使用总金额以及剩余金额。

### 4. 安全交易基线使用校验：不在 LTC 管理

1. 创建生产订单
2. 订单上线
3. 订单发货（CRM中转销订单，待发货申请的时候会校验中信保额度是否充足。未来有供应链变革项目统一做管控）

## 二、【业务方案】客户授信池管理（厂端授信 + 中信保授信）

### 1. 名称定义

**关键假设：不存在一个订单分批发货的场景 订单：交货单 = 1:1；不存在发货单部分取消的场景；不存在订单变更场景（金额减量变更）；**

| 符号 | 名称 | 定义 | 取值说明 | 数据来源 |
|---|---|---|---|---|
| A | 订单金额 | 订单（合同）的金额，即该订单应收的总金额 | 固定不变；发生合同变更（增减量）时更新 | 订单主数据 |
| A_dn | 交货单金额 | 订单下某张交货单的金额 | 整单制下订单↔交货单 1:1，A_dn = A；仅当订单可拆多张交货单时才不同 | 交货单 |
| R | 累计取消退货金额 | 订单累计被取消/退货冲掉的金额 | 整单制下只有 0 或 A（等价于「是否已取消/退货」状态） | 订单主数据 |
| S | 累计结款金额 | 订单累计被结款（解款/认款）的净金额 | S = 结款累计 − 红冲累计，≥ 0；红冲上限=已结款 | 订单主数据 |

### 2. 占用，释放授信场景定义

**业务角度**（截图 doc816-p2/comment2.png）：

| 事件 | 细分场景 | 类型 | 占用/释放金额 | 系统计算公式 | 说明（示例） |
|---|---|---|---|---|---|
| 发货单推出 | 推出时无解款（S=0） | 占用 | A_dn（全额） | max(0, A − S) | 未解款视同全部走授信；例：A=10万 → 占用10万 |
| | 推出前已有部分解款（0<S<A） | 占用 | A_dn − S | | 只占授信敞口；例：A=10万、S=3万 → 占用7万 |
| | 推出前已全额解款（S=A） | 占用 | 0 | | 先款后货，完全不占池 |
| 发货单取消 | 整单取消（取消前无解款） | 释放 | A（剩余占用金额） | max(0, A − S) | R 置 A，占用清零；例：占用10万 → 释放10万 |
| | 整单取消（取消前已有解款 S） | 释放 | max(0, A − S) | | 已解款部分池外转预收/退款；例：S=4万 → 释放6万 |
| 退货订单 | 整单退货 | 释放 | 该单剩余占用 = max(0, A − S) | max(0, A − S) | 与取消同效果（R=A 进终态），区别仅在业务触发：已发货后退回；例：占用7万 → 释放7万 |
| 解款（认款） | 交货后结款（已有占用） | 释放 | ΔS（1:1，上限=剩余占用） | ΔS | 例：S 3万→7万 → 释放4万 |
| | 交货前结款（提前结款，无占用） | 释放 | 0 | 0 | 没占用（交货还没出）→ 结款没有可释放的对象 → 释放 0 |
| 解款红冲 | 正常红冲（占用存在） | 占用 | ΔS（1:1） | ΔS | 例：S 7万→3万 → 重新占用4万 |
| | 提前结款被红冲（无占用） | 占用 | 0 | 0 | 没占用（交货还没出）→ 红冲没有可占用的对象 → 占用 0 |

**IT 角度**（截图 doc816-p1.png）：

| 事件 | 来源单据 | 触发状态 | 关联字段 | 动作 | 类型 |
|---|---|---|---|---|---|
| 发货单推出 | 交货单 | 过账 | order_no, delivery_no | checkAndOccupy | 占用 |
| 发货单取消 | 交货单 | 取消过账 | delivery_no | release | 释放 |
| 退货订单 | 退货单 | 入库完成（过账） | return_no→delivery_no→order_no | release | 释放 |
| 结款（认款） | 结款单 | 核销完成（认款） | settle_no→order_no | release | 释放 |
| 结款红冲 | 红冲单 | 过账/生效 | redcharge_no→settle_no→order_no | checkAndOccupy | 重占 |

**Why need max(0, …)**

| 负值来源 | 业务上是否应该发生 | max 的作用 |
|---|---|---|
| 超额认款 | 不应发生（已确认） | 兜底 |
| 订单金额减量 | 可能发生 | 防可用额度虚增 |
| 数据异常 | 不应发生 | 兜底 |

### 3. 基于明细的汇总计算

| 名称 | 计算公式 | 计算模块 | 备注 |
|---|---|---|---|
| 中信保批复限额 | 中信保接口获取。 | 风控模块 | |
| 中信保批复限额余额 | 中信保接口获取。 | 风控模块 | |

| 中信保净占用额度 | Σ(amount where biz_type=OCCUPY and credit_type=SINOSURE) − Σ(amount where biz_type=RELEASE and credit_type=SINOSURE) | | 上线数据处理：1.中信保期初crm占用明细（未发货） |
| 中信保批复限额上浮余额 | 中信保批复限额上浮额度 - 中信保净占用额度 | 风控模块 | |
| 厂端授信额度 | CRM 直接获取 | 风控模块 | |

| 客户授信池总额 | 中信保批复限额上浮额度 + 厂端授信额度 | 风控模块 | |
| 客户授信池余额 | 中信保批复限额上浮余额 + 厂端授信余额 | 风控模块 | |
| 合同风险赊销 | 赊销合同金额 - 合同使用现款部分额度 | 合同模块 | |
| 客户签约占用 | Σ[合同风险赊销金额 − 该合同已发货金额 + 该合同发货取消金额 + 该合同退货金额] | | 上线数据处理：中信保期初crm占用明细（未发货）+ 上线后计算；客户所有「使用赊销、双方签批归档」的合同中，尚未通过净发货转化为实际占用的赊销承诺金额。 |
| 客户风险敞口 | 厂端授信净占用额度 | 合同模块 | 已发货未回款 |

| 签约超限标记 | 交易风险敞口>0 ？超限：不超限 | | |

### 2. 数据模型（截图：用户图1/图2/图3）

**2.1 授信池主数据（customer_credit_pool）**：customer_id、factory_limit（厂端授信额度 CRM）、sinosure_official_limit（中信保官方限额 接口）、sinosure_limit（中信保限额 = 官方限额 × 1.5）、factory_occupancy / sinosure_occupancy（净占用，由明细汇总/冗余）、factory_balance / sinosure_balance（余额 = 额度 − 净占用）

**2.2 授信额度变动明细（credit_change_detail）**：id（bigint 主键流水号）、credit_type（FACTORY/SINOSURE）、biz_type（OCCUPY 占用含重占/RELEASE 释放）、amountCNY/amountUSD（decimal(18,2) 恒正）、fx_rate（汇率快照）、source_type（DELIVERY/CANCEL/RETURN/SETTLE/REDCHARGE）、source_no、related_source_id（红冲溯源，条件必填）、customer_id/customer_name、order_no、delivery_no（条件必填）、order_amount_A / return_amount_R / settle_amount_S（快照）、biz_date、operator、remark、created_at

**2.3 合同表新增字段**：credit_type（EXTERNAL外部融资/CREDIT赊销）、cash_amount（现款部分，合同风险赊销 = 合同金额 − cash_amount）、external_finance_amount（外部融资金额，合同级带到订单）

**2.4 订单表新增字段**：credit_type（FACTORY/SINOSURE，发货时判定反写）、credit_locked（授信类型是否已锁定，发货后 true）
（另有一张退货单表：return_no、order_no、delivery_no、return_amount、status（CREATED/APPROVING/WAREHOUSED/VOID）、biz_date）

**2.5 交货单表新增字段**：order_no（关联订单，唯一索引 1:1）、status（ACTIVE/CANCELLED/RETURNED，R 的来源）
