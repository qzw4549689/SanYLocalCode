## 二、批复限额主表 `mcs_approvedquota`（816 方案"中信保批复限额"的取值落点）

同步机制（PRD）：Power Apps Scheduled Flow 每日凌晨 T+1，中信保"出口险-限额信息查询"接口，按限额申请 id 幂等（存在更新/不存在新增），增量窗口=当天-7天（可配参数，配 3650 即全量）；接口只返回**已审批**的记录。

关键字段（DEV1 元数据 + UAT 真实数据实证）：

| 字段 | 类型 | 说明 | 实证发现 |
|---|---|---|---|
| `mcs_quotasum` | Decimal | 限额金额（USD） | ✅ 真实值（250000、3000000 等） |
| `mcs_quotabalance` | **String** | 限额余额 | ⚠️ **中信保侧动态余额**：UAT 出现 `-3710001.54`（负数=超额），带 `mcs_balancerecorddatestr` 测算时间；是中信保按"已申报出运"扣减后的余额，T+1 滞后 |
| `mcs_quotastate` | Picklist | 限额状态 | 0 无效 / 1 有效 / 2 预批（实证：无效记录有失效日期） |
| `mcs_applygenre` | Picklist | 限额申请类型 | 1非信用证(无担保) 2非信用证(企业担保) 3非信用证(备用信用证/保函) 4普通信用证 5保兑信用证 7/8扩展承保 |
| `mcs_paymode` | Picklist | 限额支付方式 | 1 LC / 2 DP / 3 DA / 4 OA |
| `mcs_buyerno` | String | 信保买方代码 | ⚠️ 格式如 `SAU/001238604`、`THA/036533`，还有 `*/*`（通用买方代码，归属待定）；经 `mcs_sinosure_buyercode`（买方代码主数据，带客户 Lookup）关联客户 |
| `mcs_buyername` | Lookup 客户 | | 实际落地有客户 Lookup（PRD 里的 mcs_custno 文本未建） |
| `mcs_effectdatestr` / `mcs_lapsedatestr` / `mcs_revokedatestr` | DateTime | 生效/失效/撤销日期 | ✅ UAT 真实值 |

## 三.五、对方模块已定的上浮/校验规则（《中信保出运投保申请.PRD》v1.1/v1.4，毕马威）

出运投保环节的限额校验规则（**已业务评审通过**）：

1. **投保金额上限 = 有效限额余额 × 1.8**（上浮部分=余额的 80%），**且不超过 USD 12,000,000**，二者从低；
2. 上浮比例（如 80%）系统参数可配；**21 个高风险国家不适用上浮**（伊朗、苏丹、南苏丹、古巴、委内瑞拉、也门、尼日利亚、伊拉克、阿富汗、利比亚等，清单在 PRD 规则 19）；
3. v1.4（8/5）新增：**保单级「限额上浮比例配置表」**（开始/结束时间、上浮比例、上浮金额）+ **「自掌限额配置表」**（保单维度、支付方式分信用证/非信用证、最高自掌限额）——上浮比例是**保单维度配置**，非全局固定值；
4. 限额类型含「自掌额度」（申请类型 6）；投保金额>限额余额或查不到余额 → 强制走内部审批；
5. 限额余额查询菜单：按客户/保单/限额类型/银行代码 + 出运投保明细汇总已使用金额。

### 口径差异说明（已定调：各管各的，以 816 最新要求为准）

## 四、对 816 方案的取值口径结论与风险

1. **"中信保批复限额"取值**：`mcs_approvedquota`，过滤 quotastate=1（有效）+ 当前日期在生效/失效区间内；维度是 买方代码×申请类型×支付方式 **多记录**，"官方限额"汇总成单值的口径（全类型求和 or 分非信用证/信用证）需业务确认。
2. **重复扣减风险（核心技术点）**：816 方案同时存在两个"余额"——
   - `mcs_approvedquota.mcs_quotabalance`：中信保记账，扣减时点=**出运申报**，恢复时点=收汇，T+1 滞后，可负；
   - 816 的"中信保净占用=Σ CRM 明细（OCCUPY−RELEASE）"：CRM 自己记账，占用时点=**发货过账**，释放=解款/退货。
   发货≠申报（中间窗口就是"已发货未投保清单"），两边时点不同 → **若池余额=上浮额度−CRM净占用，又拿中信保余额做校验，必然重复扣减/对不上**。建议：池计算与发货校验只用 CRM 自己的净占用（实时），中信保 quotabalance 仅作 T+1 参考+每日对账项。
3. **买方代码关联**：`mcs_approvedquota.mcs_buyerno`（格式 国家/代码）→ `mcs_sinosure_buyercode.mcs_buyerno` → 其 `mcs_customermasterdata` Lookup → 客户。`*/*` 这类通用买方代码的归属要业务确认。
4. **已发货未投保清单**：可用 `mcs_shipmentdeclare_applyinfo.mcs_ordernum`（已有 825 条）与上游已发货订单比对得出——数据源在 CRM 内，我方可以做视图。
5. `mcs_sinosure_quotaapproveinfo`（中信保额度信息，41 条空记录）疑似流程占位表，取值**不要**用它。
