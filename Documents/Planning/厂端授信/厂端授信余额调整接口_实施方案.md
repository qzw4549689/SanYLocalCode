> **创建日期**：2026-07-22
> **状态**：✅ 方案已与用户确认（含 3 个决策点），待开发

## 1. 需求理解（PRD 要点）

提供 **D365 内部统一接口**，供合同评审、订单发货/取消/退货、回款解款等业务环节调用，统一处理厂端授信余额的 **初始化 / 占用 / 释放** 三种调整动作，并写入台账。

- **额度表 `mcs_fca_quota`**：余额 = 授信额度 − 占用金额；需新增字段【厂端授信占用金额USD】
- **台账表 `mcs_fca_records`**：每次调整写一条台账（调整前余额、调整金额、调整后余额，允许负余额表示超额）
- **触发环节**：模型计算/额度申请→初始化；订单发货→占用（订单金额）；订单取消/退货、回款解款→释放
- 额度动态统一使用美元，非美元由调用方按汇率换算后传入

## 3. 接口参数设计（按 PRD 5.2）

### 请求参数

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `mcs_accountid` | String | 是 | **客户编码（SAP客户代码）**，非 GUID；接口内部按 `mcs_customermasterdata.mcs_sapnumber` 定位额度记录 |
| `mcs_usebalance` | Decimal | 是 | 调整厂端授信金额USD（≥0，调用方负责汇率换算） |
| `mcs_proccess` | String | 是 | 流程环节编码（**以台账表 1-11 为准**，见 §7.1） |

| `mcs_orderid` | String | 否 | 订单编码（同上） |

| 参数 | 类型 | 说明 |
|---|---|---|

| `mcs_usedbalance` | Decimal | 实际调整金额，失败时 0.00 |

## 4. 核心处理逻辑（按 PRD 5.3）

**公共前置**：按客户编码查 `mcs_customermasterdata`（`mcs_sapnumber`）→ 查 `mcs_fca_quota` 额度记录；客户或额度记录查不到返回失败。

### 4.1 初始化（mcs_adjust=1）

- 额度记录存在 → 更新【厂端授信额度USD】【模型计算序列号】【是否生效=是】【生效日期=当日】；不存在 → 新建额度记录
- **占用处理（决策点 A）**：新建时 `usedsellerbalance = 0`、`sellerbalance = sellergrant`；**更新已有额度时占用不清零**，`sellerbalance = 新额度 − 现有占用`
- 写一条台账（**调整金额 = 0**，决策点 B，PRD 口径）

### 4.2 占用（mcs_adjust=3）

- **重复性校验**：按「订单编号优先、为空用合同编号」+ 客户编码查台账最新记录，若最新动作已是占用 → 判定重复，返回 `usedflag=0`、`usedbalance=0.00`、`failreason="对应合同已执行占用，无法再次执行动作占用"`
- 校验通过 → 更新额度表：余额 −= 金额、占用 += 金额；写台账（调整后余额 = 余额 − 金额，**允许负数表示超额，不拦截**）

### 4.3 释放（mcs_adjust=4）

- 更新额度表：余额 += 金额、占用 −= 金额；写台账（调整后余额 = 余额 + 金额）
- **释放不做防重复校验**（已确认）

### 4.4 动作-环节交叉校验

按台账表 1-11 环节定义做白名单校验：初始化仅限环节 1（厂端授信模型计算）/2（厂端授信限额额度申请）；占用/释放按环节对应关系校验，不合法组合返回失败。

## 5. 核心不变式与连锁影响分析

### 5.0 核心不变式

> **授信额度 = 授信余额 + 占用金额**（`sellergrant = sellerbalance + usedsellerbalance`）

所有写额度表的入口（现有 3 个 + 新接口 = 4 个）必须维护该不变式。

### 5.1 FcaProcActivationPlugin（环节1 模型计算生效启用）— 需修改

现有逻辑：`sellergrant = sellerbalance = initGrant`，未写占用字段。

- **必改 1**：新建额度时补写 `usedsellerbalance = 0`
- **必改 2（决策点 A）**：更新已有额度时占用不清零，`sellerbalance = 新额度 − 现有占用`（避免清零客户已发货未回款的真实占用）
- **必改 3（决策点 B）**：初始化台账口径统一为 PRD 口径：`adjustamt = 0`、`tobebalance = 授信额度`（现有代码写的是 `adjustamt = initGrant`、`asisbalance = 0`，与新接口口径不一致会致台账混乱）

### 5.2 QuotaActivationService / FcaQuotaAppBppCallbackPlugin（环节2 额度调整申请审批通过）— 需修改

现有逻辑：审批通过 → `sellerbalance = tobeBalance`（前端 JS 计算 `tobeGrant − sellerGrant + sellerBalance`）。

- **必改 1**：`QuotaActivationService` 回写时按 `sellerbalance = tobeGrant − usedsellerbalance` 计算，**不再信任前端传入的 tobeBalance**，不重置占用字段；查询额度时增读 `usedsellerbalance`
- **必改 2**：`mcs_fca_quotaapp.js` 的 `retrieveCurrentQuota` 增查 `mcs_usedsellerbalance`，`tobeBalance = tobeGrant − used`
- **决策点 C（不予授信归零）**：grant = 0 时 `used` 保持不变、`balance = −used`（负余额代表仍有未释放敞口，后续回款释放可加回）

### 5.3 新接口 AdjustFcaQuotaBalance（本次开发）

- 占用/释放天然维护不变式；初始化按决策点 A 口径，与 §5.1 保持一致
- "查/建/更新额度 + 写台账"封装为 `FcaQuotaAdjustService`，不改动 §5.1/§5.2 的现有结构

### 5.4 mcs_credit_profile.html（客户信用画像）— 不受影响

只读汇总 `sellergrant/sellerbalance`，无需修改（可选补充显示占用金额，默认不做）。

### 5.5 元数据 / 界面 / 多语言

- **新增字段** `mcs_fca_quota.mcs_usedsellerbalance`（厂端授信占用金额USD，Money 2 位小数）
- `mcs_fca_quota` 主表单、相关视图加新字段；translations 导入补 1033/2052；`Documents/Planning/多语言翻译总表_v1.xlsx` 同步追加
- `mcs_fca_records` 无字段变更；环节选项集保持台账表 1-11 **不动**

### 5.6 历史数据初始化（PRD 3.2）— 上线前数据迁移

功能上线前需对存量额度记录一次性核算占用（已发货未回款金额），通过接口初始化动作回写 `used`/`balance` 并写台账。建议用工具批量执行，**属于上线前数据迁移任务，不随本次接口代码交付**，先记录。

## 6. 已确认决策汇总（2026-07-22 用户确认）

| # | 问题 | 结论 |
|---|---|---|
| 1 | 流程环节编码两套定义不一致（台账表 1-11 vs 接口参数表 1-12） | **以台账表 1-11 为准**，选项集不改动；PRD 接口参数表的 1-12 口径作废，接口文档中注明 |
| 2 | 客户编码定位字段 | 按 `mcs_customermasterdata.mcs_sapnumber` 匹配 |
| 3 | 占用时余额不足 | **不拦截**，允许调整后余额为负（表示超额） |
| 4 | 释放是否防重复 | **不做**，仅占用做防重 |
| 5 | 合同/订单编码查不到 | 返回失败，提示"没有找到" |
| 6 | Custom API 唯一名 | `mcs_AdjustFcaQuotaBalance` |
| 7 | 台账编号 | 使用系统统一自动编号 Plugin，本次不开发 |
| A | 再次生效启用时占用是否清零 | **不清零**，`balance = 新额度 − 现有占用` |
| B | 旧 Plugin 初始化台账口径 | **同步修正**为 PRD 口径（`adjustamt=0`） |
| C | 不予授信归零处理 | `used` 不变、`balance = −used`，保留敞口 |

> **2026-07-29 复核（禅道 #1408）**：按最新版 PRD（动态运用 PRD V1.0 §5.3 + 厂端授信管理 PRD 飞书最新版）逐条复核接口实现，结论：**决策点 1（环节 1-11）与决策点 A（初始化不清零占用）经用户再次确认维持不变**。PRD §5.3「初始化余额=额度、占用=0」按「仅适用新增场景」解读（PRD §3.2 历史占用通过占用动作补录佐证）。本次仅补齐 `mcs_usedsellerbalance` 中文标签并加主表单，接口代码无改动。⚠️ 调用注意：初始化动作入参 `mcs_usebalance` 为**新额度值**，传 0 会将额度抹 0。
