# 厂端授信：模型版本与参数配置关系确认

> **背景**：在按 PRD 实现【授信模型计算】过程中，发现【授信模型版本】与【授信参数配置】两张表之间缺少关联字段，导致 PRD 中提到的版本管理、启用/停用、历史追溯等需求无法落地。本文档用于与业务方确认设计方向。

---

## 一、当前 PRD 设计梳理

### 1.1 已明确的实体

| 实体 | 表名 | 核心字段 |
|---|---|---|
| 授信模型版本 | `mcs_fca_mdlversion` | `mcs_versionid`（V+YYYYMMDD）、`mcs_isactive`、`mcs_modeldesc`、`mcs_validfrom`、`mcs_validend` |
| 授信参数配置 | `mcs_fca_mdlconfig` | `mcs_buyergrade`（客户分类）、`mcs_creditgrade`（客户等级）、`mcs_adjust1/2/3`（系数）、`mcs_aggfunc`（聚合方法）、`mcs_countryname`（历史基准额度） |
| 授信模型计算 | `mcs_fca_proc` | `mcs_versionid`（关联模型版本）、`mcs_modelgrant`、`mcs_initigrant`、`mcs_accountid` 等 |

### 1.2 当前 ER 关系

```
mcs_fca_mdlversion ◄────── mcs_fca_proc
        （1:N，模型版本被计算记录引用）

mcs_fca_mdlconfig ──────── 独立存在，无任何字段关联模型版本
```

### 1.3 模型计算逻辑（PRD 第 778-920 行）

计算时直接按 **客户分类 + 客户等级** 去 `mcs_fca_mdlconfig` 取参数，**完全不涉及模型版本**。

---

## 二、当前设计导致的问题

| PRD 需求 | 当前设计能否支持 | 原因 |
|---|---|---|
| 自动记录公式的编辑历史、版本信息 | ❌ 不能 | 参数配置没有版本字段，编辑后旧值被覆盖 |
| 同一时间同一条件下仅启用一个默认公式 | ❌ 不能 | 参数配置全局只有一套，不存在“启用/停用”概念 |
| 停用公式可保留备用，便于后续场景切换 | ❌ 不能 | 无法保留多套参数配置 |
| 支持不同客户类型配置不同授信模型 | ⚠️ 部分能 | 可通过客户分类+客户等级区分系数，但这与模型版本无关 |
| 历史计算可追溯当时使用的公式 | ⚠️ 只能追溯版本号 | 能查到 `mcs_fca_proc` 用了哪个版本号，但查不到该版本号对应的系数配置 |

**核心矛盾**：PRD 提出了“版本管理”的业务诉求，但表结构没有把【版本】和【公式参数】关联起来，版本只能作为一个时间戳/审计标签存在。

---

## 三、建议方案：模型版本与参数配置建立 1:N 关系

### 3.1 方案概述

在 `mcs_fca_mdlconfig`（授信参数配置表）上新增一个 Lookup 字段 `mcs_fca_mdlversionid`，指向 `mcs_fca_mdlversion`（授信模型版本表）。

关系为：**一个模型版本对应多条参数配置记录**。

### 3.2 调整后的 ER 关系

```
┌─────────────────────────┐
│   mcs_fca_mdlversion    │
│     授信模型版本表        │
├─────────────────────────┤
│ mcs_fca_mdlversionid (PK)│
│ mcs_versionid            │ ← 显示编号 V+YYYYMMDD
│ mcs_isactive             │
│ mcs_modeldesc            │
│ mcs_validfrom/end        │
└───────────┬─────────────┘
            │ 1
            │
            ▼ N
┌─────────────────────────┐
│    mcs_fca_mdlconfig    │
│    授信参数配置表         │
├─────────────────────────┤
│ mcs_argid               │
│ mcs_fca_mdlversionid    │ ← 新增：关联模型版本 (FK)
│ mcs_buyergrade          │
│ mcs_creditgrade         │
│ mcs_adjust1/2/3         │
│ mcs_aggfunc             │
│ mcs_countryname         │
└─────────────────────────┘
```

### 3.3 该方案能解决的问题

| PRD 需求 | 1:N 方案如何支持 |
|---|---|
| 记录公式编辑历史 | ✅ 每版模型有独立参数配置记录，旧版本数据完整保留 |
| 同一时间仅启用一个默认公式 | ✅ 通过 `mcs_isactive=1` + 有效期控制当前生效版本 |
| 停用公式保留备用 | ✅ 旧版本 `mcs_isactive=0`，数据不删，可重新启用 |
| 不同客户类型不同模型 | ✅ 同一版本下按客户分类+客户等级配置多组参数 |
| 历史计算可追溯 | ✅ `mcs_fca_proc.mcs_versionid` → 版本 → 当时那套参数配置 |

### 3.4 计算时如何取数

1. 取 `mcs_fca_mdlversion` 中 `mcs_isactive=1` 且在当前有效期内、最新的一条记录；
2. 在该版本下，按客户分类 + 客户等级去 `mcs_fca_mdlconfig` 取精确匹配参数；
3. 若精确匹配不存在，取该版本下客户等级=ALL 的兜底配置；
4. 若仍不存在，给出默认值或停止计算（按 PRD 兜底规则）。

## 四、需要业务确认的问题

### 4.1 核心设计确认

1. **是否同意参数配置表增加模型版本关联字段，形成 1:N 关系？**
   - 如不同意，请明确“版本管理”“启用停用”“历史追溯”如何在当前表结构下实现。

2. **同一时间内，是否全局只允许一个模型版本生效？**
   - 选项 A：全局唯一生效版本（推荐，与 PRD“同一时间同一条件下仅启用一个默认公式”一致）。
   - 选项 B：允许不同客户分类/等级使用不同生效版本（复杂度更高，需重新定义“条件”）。

3. **参数配置的唯一性维度是什么？**
   - 推荐：`模型版本 + 客户分类 + 客户等级` 唯一。
   - 即同一版本内，不允许相同客户分类+客户等级的记录重复。

### 4.2 操作体验确认

4. **新增模型版本时，是否需要支持“基于旧版本复制参数配置”？**
   - 推荐支持，否则业务每次新增版本都需重新录入大量参数。

5. **参数配置是在【授信模型版本】表单内通过子网格维护，还是在【授信参数配置】独立列表中维护？**
   - 推荐：在模型版本表单中以子网格方式维护，更符合 1:N 关系认知。

6. **停用某个模型版本时，是否需要校验该版本下是否已有模型计算记录？**
   - 推荐：不需要强制校验，因为历史计算记录需要保留；但可提示“已有 N 条计算记录引用该版本”。

### 4.3 历史数据与追溯

7. **当业务修改某版本的参数配置后，之前用该版本计算出的额度是否需要重新计算？**
   - 选项 A：不重新计算，历史记录保持当时结果（审计优先）。
   - 选项 B：重新计算并更新历史记录（数据一致性优先）。

8. **是否需要记录每次参数配置的修改日志（谁、何时、改了什么字段）？**
   - D365 自带审计功能可部分满足，但字段级变更明细可能需要额外开发。

## 五、技术影响评估

如确认采用 1:N 方案，需要调整的内容如下：

| 范围 | 影响点 |
|---|---|
| **元数据** | 在 `mcs_fca_mdlconfig` 新增 `mcs_fca_mdlversionid` Lookup 字段；更新表单、视图、唯一性约束。 |
| **前端 JS** | `mcs_fca_mdlconfig.js` 保存校验需加上版本字段；`mcs_fca_proc.js` 计算逻辑需传入版本 ID。 |
| **后端 Plugin** | 模型计算 Plugin 需从“全局取参数”改为“在指定版本下取参数”。 |
| **现有测试数据** | DEV1/UAT 已创建的 `mcs_fca_mdlconfig` 记录需要补录 `mcs_fca_mdlversionid` 值，否则计算会取不到参数。 |
| **PRD 文档** | 需更新表设计章节、ER 图、模型计算逻辑描述。 |

---

## 六、推荐结论

建议采用 **【模型版本 : 参数配置 = 1 : N】** 的方案，并在 `mcs_fca_mdlconfig` 上新增 `mcs_fca_mdlversionid` 字段。该方案能完整支持 PRD 中关于版本管理、启用停用、历史追溯的诉求，且与现有“按客户分类+客户等级取参数”的逻辑兼容。

在业务确认前，不建议直接修改表结构和代码，以免后续返工。
