# D365 通用自动编号使用指南

> **适用范围**：三一 D365 客户信用评估系统 / 厂端授信额度管理模块  
> **目标环境**：DEV1 / UAT / PROD  
> **最后更新**：2026-07-01

---

## 1. 概述

项目内已封装一套**通用自动编号框架**，可在任意实体创建记录时，按预定规则自动生成编号。框架由以下部分组成：

| 组件 | 说明 |
|------|------|
| 配置实体 | `ms_numbergenerateconfiguration` |
| 通用 Plugin | `MSLibrary.D365.Common.Plugins.EntityValidateCreateForGenerateNumber` |
| 注册时机 | Create / PreValidation / Synchronous |
| 流水号服务 | 扩展服务端点 `GenerateSerialNumberService`（部署在 `tx-windows`） |
| 配置工具 | `Code/Tools/MetadataTool` |

> **注意**：该框架代码位于远程服务器 `tx-windows` 的 `MSLibrary.D365.Common` / `MSLibrary.D365.Extension` 中，**本地 SanYi 仓库不包含框架源码**，只提供配置工具。

## 2. 配置实体字段说明

配置记录保存在 `ms_numbergenerateconfiguration` 中，关键字段如下：

| 字段 | 说明 | 示例 |
|------|------|------|
| `ms_name` | 实体逻辑名 | `mcs_fca_proc` |
| `ms_attributename` | 要填充编号的字段逻辑名 | `mcs_doid` |
| `ms_prefixtemplate` | 前缀模板 | `FCM{$datetimeformat(false,yyyyMMdd)}` |
| `ms_numbertemplate` | 数字模板 | `{$prefix()}{$serialno()}` |
| `ms_serialnolength` | 序列号长度（0 表示无序列号） | `4` |
| `ms_serialnostart` | 序列号起始值 | `1` |
| `ms_useserialnoservice` | 是否使用扩展序列号服务 | `true` / `false` |
| `statecode` | 状态（0=启用，1=停用） | `0` |

### `ms_useserialnoservice` 关键区别

- **`true`**：走扩展服务端点 `GenerateSerialNumberService` 生成流水号。**当前环境必须选 true**，否则会因为调用不存在的 `ms_getserialnumber` Action 而报错。
- **`false`**：尝试直接调用 D365 原生 `ms_getserialnumber` Action。当前环境**不支持**，会报 `Request not supported ms_getserialnumber#2011/Organization.svc`。

> 经验：从 `mcs_quote_main` 等已有配置看，当前 DEV1 扩展序列号服务已正常运行，只要勾选 `使用序列号服务 = true` 即可生成带 4 位序列号的编号。

## 3. 模板语法

### 3.1 可用标签

| 标签 | 说明 | 示例输出 |
|------|------|----------|
| `{$prefix()}` | 渲染前缀模板 | `FCM20260701` |
| `{$serialno()}` | 渲染指定位数的序列号 | `0002` |
| `{$datetimeformat(false,yyyyMMdd)}` | 当前日期（UTC，按指定格式） | `20260701` |
| `{$currententity(字段名,)}` | 取当前记录某字段值 | `CN` |

### 3.2 常见规则组合

| 规则 | 前缀模板 | 数字模板 | 序列号长度 |
|------|----------|----------|------------|
| `VYYYYMMDD` | `V{$datetimeformat(false,yyyyMMdd)}` | `{$prefix()}` | `0` |
| `FCM + YYYYMMDD + 4位序列号` | `FCM{$datetimeformat(false,yyyyMMdd)}` | `{$prefix()}{$serialno()}` | `4` |
| `BL-Q-国家代码-YYYYMMDD-4位序列号` | `BL-Q-{$currententity(mcs_countryid.mcs_countrycode,)}-{$datetimeformat(false,yyyyMMdd)}` | `{$prefix()}{$serialno()}` | `4` |

## 4. MetadataTool 命令

以下命令已集成到 `Code/Tools/MetadataTool`：

```bash
cd /Users/peterqiu/Work/AIWorkSpace/SanYi/Code/Tools/MetadataTool
```

### 4.1 查询现有配置

```bash
dotnet run -- list-number-configs [实体名]
```

### 4.2 新增配置

```bash
dotnet run -- create-number-config <实体名> <属性名> <前缀模板> <数字模板> <序列号长度> [序号开始] [使用序列号服务true|false]
```

示例（无序列号）：

```bash
dotnet run -- create-number-config mcs_fca_mdlversion mcs_versionid 'V{$datetimeformat(false,yyyyMMdd)}' '{$prefix()}' 0
```

示例（4 位序列号）：

```bash
dotnet run -- create-number-config mcs_fca_proc mcs_doid 'FCM{$datetimeformat(false,yyyyMMdd)}' '{$prefix()}{$serialno()}' 4 1 true
```

### 4.3 注册通用 Plugin Step

```bash
dotnet run -- register-number-config-step <实体名>
```

### 4.4 测试编号生成

```bash
dotnet run -- test-number-config <实体名> [属性名]
```

当前支持自动构建测试记录的实体：

- `mcs_fca_mdlversion`
- `mcs_fca_proc`

其他实体请手动在 D365 UI 中新建记录验证。

### 4.5 删除配置

```bash
dotnet run -- delete-number-config <实体名> <属性名>
```

## 5. 完整配置步骤示例

以 `mcs_fca_proc.mcs_doid`（`FCM + YYYYMMDD + 4位序列号`）为例：

1. **确认字段存在**

   ```bash
   dotnet run -- list-fields mcs_fca_proc
   ```

2. **创建自动编号配置**

   ```bash
   dotnet run -- create-number-config mcs_fca_proc mcs_doid 'FCM{$datetimeformat(false,yyyyMMdd)}' '{$prefix()}{$serialno()}' 4 1 true
   ```

3. **注册 Plugin Step**

   ```bash
   dotnet run -- register-number-config-step mcs_fca_proc
   ```

4. **测试编号生成**

   ```bash
   dotnet run -- test-number-config mcs_fca_proc
   ```

   预期输出类似：

   ```
   生成编号: FCM202607010002
   ```

## 6. 注意事项

1. **不要重复创建配置**：`create-number-config` 会检查同一实体+字段是否已有启用配置，已存在则跳过。
2. **不要修改/删除他人配置**：查询与操作只针对自己负责实体的配置。
3. **Plugin Step 只需注册一次**：`register-number-config-step` 会检查是否已存在同类型 Step，已存在则跳过。
4. **序列号服务依赖远程扩展服务**：当前环境使用 `SanyD365.D365Extension` Assembly 中的 `GenerateSerialNumberService`，不需要 D365 内存在 `ms_getserialnumber` Custom API。
5. **发布到 UAT/PROD 时**：配置记录和 Plugin Step 需要随 Solution 迁移，或在目标环境重新执行上述命令。
6. **本地独立 Assembly 测试后必须注销**：如果为了调试单独注册了本地 Assembly 的 Step，测试结束后务必执行 `unregister-plugin <Assembly名>`，避免 Solution 打包失败（错误 `8004801D`）。

## 8. 故障排查

### 8.1 报错 `Request not supported ms_getserialnumber`

**原因**：`ms_useserialnoservice` 为 `false`，框架尝试调用 D365 原生 Action 但环境未部署。  
**解决**：删除配置后重新创建，显式指定 `true`：

```bash
dotnet run -- create-number-config <实体> <字段> '<前缀>' '<模板>' <长度> <开始> true
```

### 8.2 编号未生成

检查项：

1. `ms_numbergenerateconfiguration` 中 `statecode` 是否为 `0`（启用）。
2. `sdkmessageprocessingstep` 中是否存在对应实体的 Create PreValidation Step。
3. Plugin Type 是否指向 `SanyD365.D365Extension` Assembly 中的 `EntityValidateCreateForGenerateNumber`。
4. 目标字段在创建时是否留空；若已赋值，框架不会覆盖。

### 8.3 序列号不连续或重复

通用框架的序列号由扩展服务端点维护，通常按天/前缀维度递增。如出现异常，请联系负责扩展服务的同事检查 `GenerateSerialNumberService` 日志。
